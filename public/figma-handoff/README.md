# Team Gemini UI/UX 화면 분리 자료

현재 `gemini-dino-jump/public` 구현을 디자이너가 검토할 수 있도록 화면과 상태를 분리한 로컬 보드입니다.

## 열기

보드 전용 서버에서 `http://127.0.0.1:8087/figma-handoff/board.html`을 엽니다. **피그마 결과 열기**는 업로드가 완료된 보드로 이동합니다. 보드의 화면 준비가 끝난 뒤 **Figma로 복사**를 누르면 Figma 공식 웹 캡처 도구가 열립니다. 복사 기능에는 브라우저 클립보드 권한이 필요할 수 있습니다.

프로젝트 루트에서 다시 실행: `python3 -m http.server 8087 --bind 127.0.0.1 --directory gemini-dino-jump/public`

- 완료된 피그마 보드: https://www.figma.com/design/ZtFRMwuWYroJD8j3jcutrn?node-id=167-2
- 대상 페이지: 게임 (`163:22`)
- 기준: 모바일 너비 440px, 일반 화면은 전체 높이, 모달·게임은 높이 956px
- UI 원본: 기존 view 모듈과 CSS
- 예시 데이터: 점수, 닉네임, 순위, 경품, 추천 통계
- 실제 API 데이터 변경 없이 별도 fixture로 화면 구성

## 검토 순서

1. 홈과 게임 선택, 가이드의 진입 단계
2. 클래식 게임과 게임 결과의 주요 행동
3. 주머니 선택, 스크래치, 공개 후 보상 이동
4. 수령함의 빈 상태, 목록, 수령 정보 입력
5. 랭킹, 친구 초대, 혜택 안내
6. 별도 문서인 게이트 러너의 시작, 플레이, 중단, 결과

## 표현 범위

텍스트, 카드, 버튼 등 웹 DOM은 편집 가능한 프레임과 레이어로 가져왔습니다. 공통 컴포넌트 인스턴스와 클릭형 프로토타입은 구성되지 않았습니다. 게임 캔버스와 복권 코팅은 정지 이미지로 변환합니다. 흐름도는 현재 코드상의 이동 관계를 나타내며, 보드 자체가 실제 경품 지급이나 게임 검증을 실행하지는 않습니다.

현재 UI에 표시된 프로모션 문구는 원문을 보존합니다. 실제 혜택 제공 여부를 검증한 자료가 아닙니다. 무제한 표시와 게임권 차감·초대 보상 설명 사이의 일관성 등은 디자이너 검토 항목에 명시했습니다.

## 파일

- `board.html`, `board.js`: 흐름도와 화면별 보드, 공식 Figma 캡처 연결
- `render.html`, `render.js`, `fixtures.js`: 기존 화면 렌더러를 사용하는 독립 시각 검토 fixture

원래 앱의 라우터·화면·스타일·서버 파일은 수정하지 않습니다.
