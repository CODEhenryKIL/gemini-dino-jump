# 공룡 점프 1차 작업 결과 보고서 초안

작성일: 2026-09-25  
상태: 로컬 검증 및 첫 Preview READY, 원격 전체 검증 진행 중  
작업 브랜치: `codex/phase1-clean-start`

## 1. 보고 범위

이 문서는 게이트러너 제거 기준에서 다시 시작한 공룡 점프 1차 작업의 현재 구현 상태와 검증 증거를 정리한다. 대상은 익명 참여자 복원, 게임권·초대권, 공룡 점프 결과 검증, 참가자당 1회 복주머니, 합성 수령 정보, 잠정 TOP3 연락 접수, 실제 Supabase Auth 관리자 로그인, 수동 연락·지급 원장, 개인정보를 제외한 단계별 지표, 전용 Supabase 스키마와 접속 역할이다.

현재 문서는 중간 결과 보고서다. 별도 주소 할당, 원격 5,000명 부하 검증과 관리자 멤버십 최종 반영이 끝나지 않았으므로 1차 전체 완료로 판정하지 않는다.

## 2. 구현 결과

### 참여자·게임권·초대

- 참여자는 `HttpOnly`, `SameSite=Lax` 쿠키로 복원하며 브라우저 저장소에 참여자 인증 토큰을 저장하지 않는다.
- 최초 기본권은 정확히 1장 지급하고, 이후 초대권은 최대 3장까지 보유한다.
- 초대권 잔액이 3장이 되는 순간 10시간 추가 적립 대기를 시작한다. 대기 중 방문은 이후 자동 이월하지 않는다.
- 초대 방문은 화면이 보이는 상태에서 3초 이상 활동하고 클릭 또는 터치이 있어야 서버 판정을 요청한다.
- 잘못된 초대 코드, 자기 초대, 잔액 가득 참, 대기 중, 중복 관계를 서버 판정 사유로 분리한다.
- 공유 식별자는 인증값과 분리된 불투명한 `share_id`이며 초대 보상 중복 방지는 행사·초대자·방문자 관계를 기준으로 한다.

### 게임·장애 복구

- 기존 공룡 점프 물리 엔진과 조작 안내를 유지하면서 서버가 세션, seed, tick, 입력 결과를 검증한다.
- 정상 충돌은 정상 완료로 처리하고 자발적 이탈은 장애 환급으로 처리하지 않는다.
- 결과 전송 응답이 유실되면 PII나 인증값이 없는 최소 결과 payload와 같은 재시도 키를 세션 저장소에 보관해 서버 결과를 먼저 조회한다.
- 네트워크·클라이언트·서버 장애는 세션 ID, 사유, tick, 재시도 ID만 보관하고 서버 체크포인트와 대조한 뒤 장애 심사를 요청한다.
- 기본권과 초대권의 소비·예약·환급은 서버 원장으로 처리하며 초대권 복구 중 보유 한도를 넘기지 않도록 별도 예약 수량을 반영한다.

### 복주머니·수령·랭킹

- 정상 검증 게임을 완료한 참가자는 행사당 복주머니를 한 번만 열 수 있다.
- 주머니 선택 뒤 서버에서 결과를 한 번 확정하며, 새로고침하거나 다시 접속해도 같은 결과를 돌려준다.
- 스크래치 완료는 서버 저장 성공 뒤에만 완료 이벤트로 기록하며 응답 유실 시 같은 키로 재시도한다.
- 실제 쿠폰 자동 발급 없이 관리자가 연락하고 지급 상태를 수동 변경한다.
- 잠정 TOP3 연락 요청은 현재 순위가 내려가거나 결과 화면을 벗어나도 유지한다. 랭킹 화면에서 다시 접수할 수 있으며 최종 수상 확정과 구분한다.

### 관리자·지표

- 관리자 로그인은 실제 Supabase Auth 비밀번호 로그인을 사용한다. 서버가 별도 관리자 멤버십과 권한을 다시 검사한다.
- 수령 연락 정보와 TOP3 연락 정보는 `claims:read` 권한이 있는 운영 업무 화면에서만 표시하며 분석 이벤트와 지표 표에는 포함하지 않는다.
- 수령 상태, 담당자, 버전, 사유, 외부 전달 여부를 낙관적 잠금과 감사 기록으로 관리한다.
- 장애 환급은 서버 증거와 체크포인트를 바탕으로 자동 승인 또는 관리자 승인·거절 상태를 구분한다.
- 초기 관측, 로딩 구간, 화면 체류, 게임 단계, 초대, 복주머니, 스크래치, 수령, TOP3, Gemini 노출·클릭을 기록한다.
- 관리자 지표에는 분자·분모, 고유 참가자, 이벤트 수, 관찰 구간, 원 집계·추정 구분, 합성 데이터 여부와 지표 정의를 표시한다.
- 개인정보, 참여자 ID, 인증값, 초대 코드, 전체 URL과 임의 query string은 분석 payload에 넣지 않는다.

## 3. 로컬 검증 증거

### 자동 검증

| 항목 | 현재 결과 |
| --- | --- |
| Node 프론트 회귀 테스트 | 23개 통과 |
| 부하 도구 보호 테스트 | 16개 통과 |
| JavaScript 구문 검사 | 통과 |
| Python compileall | 임시 pycache 경로를 사용해 통과 |
| Git whitespace 검사 | `git diff --check` 통과 |
| 최종 통합 테스트 | Python 66개 통과 |

Python 66개 검사에는 실제 PostgreSQL 기능·동시성·보안·5,000명 합성 데이터 생성/재개 검사가 포함된다. 최종 TOP3 지급 차단 수정 후에도 66개가 통과했다.

### 실제 브라우저·로컬 PostgreSQL

- 쿠키 참여자 복원과 게임권 0장 상태의 진행 중 세션 복원 진입을 확인했다.
- 동일 게임 세션을 복원해 실제 엔진 충돌까지 실행했고 서버가 `score=32`, `ticks=194`, `FINISHED`, `VERIFIED`로 저장했다.
- 결과 화면에서 최고 점수 32점과 현재 랭킹 1위를 확인했다.
- 한 참가자의 복주머니가 `NO_PRIZE`로 확정된 뒤 새로고침·재접속에서도 동일 결과가 유지되는 것을 확인했다.
- 잠정 TOP3 연락 정보의 합성 테스트 접수를 실제 브라우저에서 완료했고, 결과 화면을 잃은 뒤에도 랭킹 화면에서 접수 진입이 유지되는 것을 확인했다.
- 실제 Supabase Auth 관리자 계정으로 관리자 화면에 로그인했다.
- 관리자 화면에서 수령 연락 정보와 TOP3 연락 접수 정보가 권한 있는 별도 업무 표에 표시되는 것을 확인했다.
- 숨김 관리자 영역과 로딩 스플래시가 로그인 전 또는 로딩 완료 뒤 접근성 트리에 남지 않는 것을 확인했다.

- 새 Supabase 프로젝트를 만들지 않고 사용자가 승인한 기존 프로젝트 안에 공룡 점프 전용 `dino_dev` 스키마를 구성했다.
- 두 migration과 명시적 합성 seed를 적용했다.
- 전용 역할 `dino_dev_app`으로 SSL `verify-full` 연결을 성공시켰다.
- 전용 역할은 필요한 `dino_dev` 범위에만 접근하도록 구성했고 기존 `public`, 기존 `dino`, Auth, Storage 데이터를 초기화하지 않았다.
- 원격 적용 전후 기존 데이터 보존을 확인했다.

### 기존 프로젝트에서 관측된 별도 보안 항목

- 기존 `public` 영역 함수에서 `search_path` 또는 `SECURITY DEFINER` 관련 경고가 관측됐다.
- Supabase Auth의 유출 비밀번호 보호 설정이 꺼져 있는 상태가 관측됐다.
- 두 항목은 이번 공룡 점프 전용 `dino_dev` 구현 이전부터 존재한 기존 영역이며, 기존 서비스 영역을 임의로 변경하지 않는 범위 원칙에 따라 이번 작업에서는 수정하지 않았다.
- 최종 보고서에는 영향 범위와 후속 권고를 별도 보안 관찰 항목으로 보완한다.
