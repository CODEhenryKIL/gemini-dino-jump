# 공룡 점프 전체 수동 테스트

작성: 2026-09-29 · 기준 브랜치: `codex/phase3-launch` · 문서 작성 시 코드 기준: `928d335` (후속 문서 커밋 `73213da`).

**이 문서는 실행 절차다. 실행 결과를 미리 통과로 표시하지 않는다.** 일반 검사는 미실행, 준비·결정이 필요한 항목은 대기로 시작한다. 기존 자동 테스트 통과를 이번 수동 테스트의 통과로 옮겨 적지 않는다. 실행 전에 실제 사이트의 배포 ID와 코드 버전을 기록한다.

총 **217개 수동 시나리오**(화면·운영 168개 + 서버 49개)를 준비했다. 기존 **55개 테스트 파일의 461개 정의**는 별도 대응표에 모두 수록했다. 화면 검사부터 시작하고, 문서 내 검색으로 `DR-10`처럼 ID를 찾으면 된다. 준비·결정이 필요한 항목은 결과 칸에 대기 상태를 미리 표시했다.

## 1. 시작 전에

### 1.1 사용할 환경

| 표기 | 환경 | 할 수 있는 검사 / 주의할 점 |

| B | [현재 베타](https://google-korea-team-gemini.vercel.app/) | 일반 화면과 정상 흐름. 게임 무제한 유지. 기존 참여·수령 기록이 있으므로 초기화하지 않는다. 실제 경품 77개 풀과 동일하지 않다. |

현재 베타의 무제한 표시로는 게임권 차감·환급 여부를 판정할 수 없다. 제한 모드 L에서 잔액과 원장을 함께 본다. B에서 데이터 삭제, 재고 강제 당첨, 날짜 변경, 가짜 웹훅 전송, 대량 요청은 하지 않는다. 실제 연락처가 있을 수 있으므로 화면 캡처·로그를 공개 저장소에 그대로 올리지 않는다.

로컬은 [README 실행 절차](../README.md#로컬-실행)에 따라 Python 3.12와 별도 PostgreSQL을 준비하고 `./run.sh`로 켠다. 기본 주소는 `http://127.0.0.1:3000`이다. 기존 3109 등 포트가 살아 있다고 가정하지 않는다. `public/index.html`을 파일로 직접 열면 API 검증이 되지 않는다.

### 1.2 참가자와 데이터 준비표

각 상태는 별도 참가자 또는 별도 테스트 캠페인으로 준비한다. 기존 베타를 초기화해서 맞추지 않는다. 준비가 안 된 경우 `준비 대기`로 표시한다.

| 코드 | 필요한 상태 |
| --- | --- |
| U0 | 새 브라우저 프로필, 게임·추첨 기록 없음 |
| U1 | 제한 모드, 최초 기본권 1장, 초대권 0장 |

예시 점수는 UI 확인용이다. 브라우저 숫자만 바꿔 순위·재고 검증을 통과 처리하지 않는다. 데이터 준비는 개발자가 테스트 factory 또는 별도 seed로 수행하고 준비한 값을 기록한다. 테스트용 이름·학교·연락처만 사용하며, 베타 형식 검증에 맞는 합성 값은 개발자가 제공한다.

### 1.3 공통 실행 방법

1. [실행 기록 양식](manual-test-results-template.md)을 복사하고 URL·배포 ID·브라우저·기기·참가자 별칭을 적는다.
2. 각 행의 **준비 → ①②③ 순서 → 예상 결과**를 모두 확인한다. 한 행에 여러 조건이 있으면 조건별 하위 결과도 남긴다.
3. `미실행`을 `통과 / 실패 / 준비 대기 / 결정 대기 / 보류`로 바꾼다. 예상 결과 일부만 맞으면 통과가 아니다.
4. 잔액은 **기본 게임권 / 초대 게임권 / 뽑기권 / 사용 추첨 횟수**를 따로 적는다. 카카오 `전송 확인`과 `보상 적립`도 따로 적는다.
5. F는 개발자가 격리 환경에서 조작한다. 단순 새로고침만으로 동시성·응답 유실을 검증했다고 쓰지 않는다.
6. 테스트 후 네트워크 차단·지연·글꼴 확대·모션 설정을 원상복구한다. 서버 데이터 정리는 테스트 run의 범위가 확인된 뒤 담당자가 한다.

### 1.4 우선 확인할 짧은 순서

전체 검사를 대체하지 않는 빠른 확인: **EN-01 → HM-01 → GU-01 → GM-01 → RS-01 → RK-03 → DR-02 → DR-05 → BN-01 → NV-01**. 이후 제한 모드·카카오·관리자·서버 항목을 진행한다.

## 17. 완료 판단

- 참가자 정상 흐름만 성공한 것은 서버·카카오·운영까지 완료했다는 뜻이 아니다. 실행한 환경과 기기를 결과에 함께 쓴다.
- 금전성 재고, 권리 중복 지급, 타인 정보 접근, 기록 유실, 계속 게임을 못 하는 문제는 출시 전 해결 대상으로 분류한다.
- 실제 카카오 DRAW 적립, 실기기 표시, 최종 부하, 운영 미정값은 현재 완료로 체크하지 않는다.
- 테스트 중 발견한 현행 동작과 확정 요구사항의 차이는 버그로 남긴다. 문서의 기대값을 동작에 맞춰 조용히 낮추지 않는다.
- 모든 자동 검증 내부 조건이 화면에서 관찰되지는 않는다. [서버 문서](manual-test-server.md)와 [전체 대응표](manual-test-coverage.md)의 관련 파일·하위 변형을 개발자와 대조한다.
