## 게임 저장·장애 복구의 늦은 응답 보완

- 게임 종료 저장 또는 보류 결과 복구 중 화면을 떠난 경우, 뒤늦은 성공·실패가 현재 화면을 결과/오류 화면으로 바꾸지 않는다. 미확인 완료 기록은 다음 복귀에서 서버 결과를 조회할 수 있게 유지하고, 다른 게임의 보류 기록을 삭제하지 않는다.
- 체크포인트·장애 보고는 요청을 시작한 세션·단계에 고정한다. 이전 게임의 응답이 새 게임의 저장소나 장애 표시를 변경하지 못하게 하고, 역순 응답으로 체크포인트가 과거 tick으로 돌아가지 않도록 했다.
- 장애 복구 화면의 조회·갱신에도 화면 수명 검사를 적용했다. 게임 준비 중 만들어진 정상 예약 snapshot은 이어하기를 위해 유지한다.
- 지연 성공/실패·역순 체크포인트·정리 후 응답·장애 체크포인트 409 재조정 행동 회귀를 추가했다. 내부 변수명에 의존하던 일부 정규식 검사를 행동 검증으로 대체했다. 전체 Node **116개** 통과. 서버 게임 규칙·점수 재현·초대 제한은 변경하지 않았다.

## 확인한 증거

### 자동 테스트

- 이전 코드 기준 로컬 전체 Python 회귀: **169개 통과** (`python -m unittest discover -s tests -p 'test_*.py' -v`). 이후 공유·복주머니 계측 변경 관련 로컬 DB 회귀 **13개 통과**. 부하 보류 중 전체 동시성 테스트를 다시 실행하지 않았다.
- 전체 Node 화면·게임 테스트: **144개 통과** (`node --test tests/*.test.cjs`). 긁기 통계 변경 관련 로컬 PostgreSQL 회귀 **5개 통과**.
- `git diff --check` 및 변경 Python/JavaScript 문법 검사 통과.
- 새 게임 JS/Python 비교에서 동일 seed/입력으로 코인 점수·하트 획득·2회 부활·최종 충돌 결과 일치를 확인했다.
- 로컬 migration 신규 DB 적용·반복 적용, 범위 밖 테이블 보존, 별도 점수 테이블 연결 검증을 포함한다.

### 실제 로컬 브라우저

Codex 내장 Chromium, 로컬 Python 서버 + 실제 로컬 PostgreSQL. 원격 성능 또는 실물 휴대폰 결과가 아니다.

- 최초 준비 → 홈 → 게임권 소비 → v2 정상 충돌 32점 → 서버 검증 → 1위 결과 표시.
- 2번 복주머니 선택 → 미당첨 확정 → 긁기 보조 버튼 → Gemini 안내.
- 새로고침 후 같은 참가자·게임권 잔액 복원.
- 혜택 화면의 공부 가이드 링크 실제 클릭. 서버 DB에서 `content_clicked` 확인.
- 로딩 데이터/연출/화면 준비, 게임 승인/완료, 추첨 확정/화면 공개, 보조 긁기, 가이드 카드 노출이 각각 저장됨을 확인.
- 혜택 화면 320/390/768/1440px에서 가로 넘침 없음. 정상 `localhost:3103` 흐름의 콘솔 오류·경고 없음.
- 이전 테스트의 다른 pepper로 생성된 쿠키는 401 복구 안내를 보였으며, 임의 새 참가자로 바꾸지 않았다.
- 새 로컬 참가자로 플레이 → 0이 아닌 점수에서 홈으로 이탈 → 새로고침 → 같은 게임 이어하기 → 저장된 2점부터 재개 → 32점 정상 종료·서버 승인까지 확인했다. 기본권은 추가 지급되지 않았다.
- 초대권은 로컬 합성 친구의 정상 유효 방문 API로 적립하고, 복귀한 브라우저에서 지급/사용량 갱신을 확인했다.
- 새 참가자가 테스트 커피에 당첨된 경로에서, 긁기 전 실제 접근성 트리에 경품명이 없고 Enter로 공개한 뒤 나타나는 것을 확인했다. 공개 후 키보드 초점도 다음 CTA로 이동하도록 보완했다.
- 로컬 브라우저 DB에 수령 상태 migration이 누락된 것을 발견해 적용했다. 정보 미입력 시 `정보 입력 대기`, 확인란 누락/잘못된 합성 연락처 제출 시 폼·입력 보존, 정상 합성 접수 후 `정보 접수` 표시와 새로고침 복원, 이후 Gemini 이동을 실제 화면에서 확인했다.
- iPhone Safari·Android·카카오톡/Instagram 인앱 브라우저 실기기와 실제 네이티브 공유는 아직 검증하지 않았다.

## 비밀 설정 노출 점검

- 2026-09-26 현재 Git 추적 파일 170개의 내용을 기존 DB URL·DB 비밀번호·쿠키 비밀값과 대조했으며 일치 항목은 없었다. 로컬 비밀 입력 파일 두 개는 소유자만 읽고 쓸 수 있는 `0600` 권한이다.
- 서버 공개 설정은 공개용 Supabase 키만 제공하고 DB 비밀번호와 쿠키 비밀값을 포함하지 않는다. 서버 요청 로그는 상태 코드·route·시간·오류 분류를 남기며 원본 접속 문자열을 출력하지 않는다.

## 다음 검증과 3차 인계

1. 사용자 화면·기능 개선을 우선하고, 개선본 Preview에서 공유 URL·쿠키·원격 당첨 수령·관리자 집계를 추가 확인. 게임·수령 전 흐름과 실기기 검증이 모두 끝난 상태는 아니다.
2. [2차 부하 계획](phase2-load-plan.md)은 **2026-09-26 사용자 지시로 보류**한다. 사용자가 재개를 요청하기 전에는 참가자 준비·원격 부하를 진행하지 않는다. 기존 계획의 시간/요청 한도는 제안값이며 승인된 예산이 아니다. 1차 시험 예산은 그대로 보존한다.
3. [로컬 브라우저 프레임·10회 엔진 정리·실제 앱 10판 측정](phase2-browser-performance.md)을 완료했다. 실제 GameView·화면 전환·점수 저장·시작/완료 이벤트·관리자 집계 함수까지 대조했다. 실기기·인앱 브라우저·네이티브 공유는 추가 검증 범위다. HTTP 테스트로 모바일 FPS 통과를 대신하지 않는다.
4. 실제 경품/확률/재고/기간, 대학생 인증 방식, 개인정보 안내, 동점 최종 수상 규칙, Google 공식 혜택은 3차 확정.
5. 4.26 체험담·사진 예시는 실자료를 받아 확정한다. Notion 내부 공식 CTA는 2차 지시서의 미완료 항목이다. 공개 열람은 가능하지만 현재 연결 계정에서는 두 원문 모두 조회되지 않아, 편집 가능한 계정 연결 또는 사용자의 명시적 3차 이관 결정을 요청했다. 직접 링크 블록은 [콘텐츠 초안](phase2-content-drafts.md)에 준비했고 경유 추적은 승인하지 않았다.
6. 전체 요구와 증거의 대응은 [2차 완료 대조표](phase2-completion-audit.md)에 정리했다. 부하 보류와 Notion 게시 제약을 기능 완료로 간주하지 않는다.
