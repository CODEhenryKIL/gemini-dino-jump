## 검증 범위와 한계

- 최신 전체 회귀: Python 388 실행/386 통과/조건부 2 생략, JavaScript 299 통과. 이후 승인 설정 fixture 집중 34개, 마지막 인증 안내 집중 2개 통과. 마지막 두 문장 변경으로 게임·추첨·경품 정책은 바뀌지 않았다.
- 부하 500개 흐름·5,502회 요청의 오류/429/timeout은 0. 200명 추첨 p95 4.875초로 1초 목표 미달이며 사용자가 수용했다. 원격 게임은 100점 이하만 실행했으므로 고득점·부활의 원격 대규모 검증으로 표현하지 않는다.
- 휴대폰 확인은 사용자 기기의 점프·키보드·큰 글씨·입력 확대·수령 자기 전송 범위다. 모든 장치·접근성 조합을 보증하지 않는다.
- 최종 공유 수정은 버튼 줄바꿈뿐이다. 카드 payload가 유지돼 기존 실제 DRAW 전송·카드 확인을 적용한다. 모든 위치의 새 수신 카드 캡처를 확보한 것은 아니다.
- 오래 열린 베타 화면은 요청 시 서버 인증 실패와 새로고침 안내를 받는다. 자동 새로고침/배너는 없으며 조용한 상태 갱신 오류는 화면에 표시되지 않을 수 있다. 베타 기록이 운영 기록으로 들어가지 않는 서버 보호는 별도로 검증했다.
- 다른 앱의 삭제 전후 전체 집계는 저장되지 않아 직접 비교하지 못했다. 실행 SQL과 원격 외래키·DELETE 트리거·쓰기 규칙을 대조해 **이번 초기화가 다른 앱에 쓰기를 일으킬 경로가 없음**을 확인했다. 다른 주체의 동시 작업까지 포함한 전체 행 수 일치 주장과 구분한다.
- 실제 Vercel 별칭 장애는 유발하지 않았다. PostgreSQL 복구 리허설·OFF 후보·복구 도구 준비를 확인했다. 복귀 시에는 새 snapshot과 계획을 생성하고 본행사 기록을 보존한다.
- Production에 시험 참가자·게임·추첨·가짜 GA4 이벤트를 주입하지 않는다. 실제 첫 진입과 GA4 보고서 수신은 관측 후에만 완료 처리한다.
