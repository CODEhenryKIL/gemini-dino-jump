## 재현된 개선 항목

### P0 — 동점 정책 구현 누락

- 실제 응답: `GET /api/leaderboard` → `tie_policy: UNDECIDED`
- 새 운영 결정: 같은 점수면 먼저 달성한 참가자를 우선한다. 현재 최고점 `achieved_at`은 게임 완료 검증 후 저장 시각이므로 게임 중 달성 시각과의 차이를 구현할 때 명시해야 한다.
- 영향: 최종 TOP3 지급 확정 규칙을 서버·관리자 snapshot에 적용할 수 없다.
- 개선: 랭킹 표시·TOP3 대상·최종 지급 순위의 정렬 기준을 일치시키고, snapshot/award 생성 시 `score DESC, achieved_at ASC`와 안정적인 최종 보조키를 사용한다. 기존 snapshot은 자동 재작성하지 않는다.

### P1 — 과도한 query field가 500

- 재현: 21개 query field를 가진 `GET /api/health`
- 실제: `500 INTERNAL_ERROR`
- 개선: `parse_qs(..., max_num_fields=20)`의 `ValueError`를 요청 검증 오류로 변환해 400 또는 414로 응답하고, 기존 구조화 로그에는 값 없이 오류 코드만 남긴다.

### P1 — 닉네임 제어문자 허용

- 재현: `PATCH /api/me/profile`에 내부 줄바꿈이 포함된 닉네임
- 실제: HTTP 200, 줄바꿈이 저장됨
- 개선: 수령 정보 입력과 같은 방식으로 C0/DEL 제어문자를 거부한다. 공개 여부 `is_public` 보존 동작은 유지한다.

## 운영 전 남은 검증

1. 새 행사 날짜가 들어간 manifest/preflight는 root가 별도 재실행해 10/10 통과했다. 실행 범위는 종합 보고서 참조.
2. 동점 우선 정책을 구현하고 동점·snapshot·최종 award 회귀를 추가한다.
3. 실제 카카오 친구/단체방 GAME·DRAW·NONE·수령 접수는 root와 사용자가 별도로 확인 완료했다. 본 문서의 SV-023 미실행은 격리 백엔드 담당 범위만 뜻한다.
4. 실제 부하는 현재 보류 상태를 유지한다.
5. 코호트 재개 opt-in 검사는 충돌 없는 전용 DB 이름을 받도록 테스트 guard를 개선한 뒤 실행한다.
