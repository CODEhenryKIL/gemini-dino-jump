# Phase 1 API contract (implementation coordination)

JSON endpoints preserve current response fields where useful. All errors: `{ "error": "CODE", "message": "safe Korean message", "request_id": "opaque UUID" }`, appropriate HTTP status; no credentials, SQL, personal data or raw exception text. All API responses are `Cache-Control: no-store`.

## Transport / business boundary

- `server/db.py`: psycopg connection context, autocommit=True, dict rows; business runs inside an explicit `conn.transaction()` which exits before success is sent.
- `server/services/operations.py`: `dispatch(conn, method, path, body, query, context) -> (http_status, dict)` and `DomainError(code, message, status=400)`. No internal commits, HTTP calls, environment reads or connection creation. Context includes `environment`, `base_url`, `benefit_url`, `game_version`, `participant_token_hash`, `new_token_hash`, `admin_user_id`, `request_id`, `synthetic`, and optional `verification` from the preserved Python verifier. Use UTC timestamptz in DB; return UNIX seconds for existing frontend date compatibility.
- Backend authenticates `participant_token_hash` against DB; checks membership for `admin_user_id` even after transport validates Auth identity. Raw participant session tokens are only returned once at creation and never stored, logged or put in events.
- Finish transport reads owned session using dispatch GET before simulation, validates input limits, computes verification outside a transaction, then dispatches finish in a fresh transaction. Finish locks/rechecks owner, ACTIVE status, timestamps, version and existing result. Immutable finish result is returned on every retry.
- Same owner retries on create session (`Idempotency-Key` copied to body `idempotency_key`), start, finish, draw (unique session), scratch and claim (unique claim) return stable shape and one effect. Existing-result ownership checks precede return.

## Player endpoints

- `GET /api/config`: `{environment, base_url, benefit_url, supabase_url, supabase_publishable_key, web_analytics_enabled, game_version}`. Public config has no backend key or DB credentials.
- `GET /api/health`: `{status, environment, game_version, database: "ok", project_ref}`; DB/config failure is 503 without fake healthy response.
- `GET /api/campaign`: `{id,title,status,game_version,benefit_url,settings:{initial_tickets,referral_reward,referral_daily_limit,referral_total_limit,claim_ttl_seconds},prizes:[...],is_test,real_prizes_enabled:false}`. Unfinalized production policy defaults to disabled; seed uses explicit test values only.
- `POST /api/participants/anonymous`: body `{referral_code?,channel?}`; response `{participant:{id,nickname,is_public,referral_code},session_token,referral_applied:false|true}`; raw new token generated by transport and hash passed to service. Synthetic flag is server environment-derived, never trusted from body.
- `GET /api/me`: `{participant,tickets,best_score,referral,pending_draw,active_session,pending_claims}`. `pending_draw` includes `{id:session_id,session_id,score,draw?}` for verified sessions with no draw or unfinished scratch. `active_session` includes id/status/expiry; expires safely, never blocks indefinitely.
- `PATCH /api/me/profile`: `{nickname,is_public}` -> `{participant}`.
- `POST /api/game-sessions`: `{idempotency_key}` -> `{session_id,seed,status,version,expires_at}`. Reuses existing live session when appropriate; reserved sessions do not consume tickets.
- `POST /api/game-sessions/{id}/start`: consumes one ticket exactly once, returns `{session_id,seed,status,version,expires_at,tickets}`.
- `POST /api/game-sessions/{id}/abort`: ends an owned RESERVED/ACTIVE session, idempotent; no automatic refund for a started game.
- `GET /api/game-sessions/{id}`: owned `{session_id,seed,status,version,expires_at,result?,draw?}`.
- `POST /api/game-sessions/{id}/finish`: `{score,valid_ticks,jump_ticks,version}` -> stable `{session_id,score,best_score,rank,verification_result,eligible_for_draw}`. Rejected results are recorded but never ranked, referred or allowed to draw.
- `POST /api/draws`: `{session_id,pouch_index}` -> `{draw_id,session_id,pouch_index,is_won,prize:{id,name,category,image_url},claim_id,scratch_completed,is_test}`; atomic eligibility + draw + locked inventory + claim. A completed draw is never re-rolled.
- `PATCH /api/draws/{id}/scratch-complete`: owned draw, returns same draw shape with scratch_completed=true.
- `GET /api/claims`: `{claims:[{id,draw_id,prize_id,prize_name,prize_category,status,expires_at,created_at,is_test,coupon_code?}]}`; only owner's data.
- `POST /api/claims/{id}/submit`: body `{recipient_name,contact_phone,shipping_address,consent:true}` (only required category fields). Development accepts synthetic values only. Returns stable `{claim_id,status,coupon_code?,is_test}`. Submission does not imply delivery. Explicit fake provider may confirm test delivery; production has no fake issuing path.
- `GET /api/referrals/me`: `{invite_url,referral_code,summary:{invited_count,qualified_count,rewarded_count,earned_tickets},policy}`.
- `POST /api/referrals/attribute`: `{referral_code}` -> `{applied:true|false}`; no false saved-success.
- `POST /api/benefit-verifications`: record interest only, never certify external signup/student status; return `{status:"PENDING",verified:false}`.
- `GET /api/leaderboard`: query `limit` bounded; `{leaderboard:[{rank,nickname,score,is_me}],my_rank,my_score}`.
- `POST /api/events`: `{events:[{event_id,event_name,screen?,active_ms?,channel?,error_code?}]}` max 20. Client allowlist: page_view,page_engagement,draw_open,claim_start,invite_copy,invite_share_open,gemini_link_click,client_error. Server-derived participant/environment/synthetic only. Server transaction emits game_start,game_finish_verified/rejected,draw_result,claim_submit,referral_qualified,referral_reward_granted. Duplicate event_id has one effect. Never accept arbitrary payloads or identifiers from browser.

## Admin endpoints

Admin uses Supabase Auth access token in Authorization. HTTP layer validates identity at `/auth/v1/user`, database checks `dino.admin_member` active membership; user_metadata is never authorization.

- `GET /api/admin/overview?from=YYYY-MM-DD&to=YYYY-MM-DD&environment=...`: `{totals,inventory,screen_metrics,channels,funnel,referrals,definitions,period:{from,to,timezone:"Asia/Seoul"},generated_at}`. Period is inclusive local days converted to UTC. Default environment is current environment, production excludes synthetic records. Definitions expose denominators and estimated exits. All relevant aggregation is server-side.
- `GET /api/admin/scores/suspicious`: `{sessions:[{id,score,verification_result,created_at}]}` without tokens or input logs.
- `POST /api/admin/campaign/status`: `{status,reason}`; validate reason and audit actor/time/target/before/after/reason.
- `POST /api/admin/tickets/adjust`: `{participant_id,delta,reason,idempotency_key}`; prevent negative balance, audit once.
- `GET /api/admin/claims`: synthetic request metadata/status only; separate explicit privilege required before exposing recipient information (phase1 UI does not need PII).

No active player Realtime subscriptions. No engine-frame network traffic. Active sessions expire; results and incomplete draws/claims remain discoverable after navigation or response loss.
