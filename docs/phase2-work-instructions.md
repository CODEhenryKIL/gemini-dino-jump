0. 목표와 경계
1차에서 구현한 서버 규칙과 측정 기반 위에 실제 사용자용 화면을 완성한다. 원문의 유입 → 로딩 → 게임 → 재도전 → 복주머니 → 보상 공개 → 수령/Gemini 흐름을 유지하되, 친구나 모든 재도전을 기다려야 복주머니를 받는 병목은 공통 문서의 편집 적용에 따라 제거한다.
이번은 코드로 구현된 최종 Preview와 문구·상태·계측 검증까지 수행한다. 최종 경품·운영 시각·공식 혜택은 미정이면 placeholder를 사용한다. 실제 공개와 선물 지급은 3차다.
1. 시작 점검
- 1차 실제 구현 상태·남은 오류·정책표를 읽고 기존 작업을 보존한다.
- 화면마다 목적, 주요 CTA, 보조 CTA, 표시 데이터, 진입/복귀/실패 상태와 트래킹을 먼저 정의한다.
- 기존 공룡 점프 시각 자산과 사용자가 제공한 디자인을 우선 재사용한다. 새로운 전체 디자인 시스템을 임의로 만들지 않는다.
- 현재 실제 화면의 디자인 느낌·방향·에셋 활용을 유지한다. 피그마 화면 렌더러와 관련 문서는 구현 기준에서 제외한다. 홈 화면 좌측 상단에 있던 팀 Gemini 로고는 상단 중앙에 배치하고 조금 키운다.
- 1차 API/DB를 화면에서 직접 우회하지 않는다. 규칙 변경이 필요한 경우 명세·서버·클라이언트·테스트·이벤트 버전을 함께 변경한다.
- 1차가 아직 작업 중이면 화면 명세·콘텐츠 초안은 병행 가능하나 같은 파일을 덮어쓰지 않게 브랜치/계약 기준을 고정한다.
2. 화면별 구현
2-1. 유입 — 링크 클릭 전
원문 목적: 진입장벽 없이 누르고 싶게, 신뢰·상품·수령 가능성 전달.
- 초기 홍보, 재도전 초대, 경품 결과 공유의 링크/미리보기·공유 문구를 분리한다.
- 대학생 경품 수령 대상, 운영팀, 랭킹 상품/복주머니 상품을 구분해 보여준다.
- 게임은 대학생이 아니어도 참여 가능하며 경품 수령 자격만 대학생으로 제한한다. 게임 시작 전에 재학생 인증을 추가하지 않는다. 대학생 대상 행사 문구와 함께 경품 수령 대상임을 알 수 있게 안내한다.
- 초기 홍보와 학교별 배포용 링크에 식별 코드를 연결하되 매체·학교와 링크 목적을 별도 관리한다.
- 결과 공유 카드에는 공개 닉네임·점수·경품명 등 승인된 공개 정보만 사용한다. 연락처·학생증·비공개 수령 링크·인증 토큰은 노출하지 않는다.
- D14 확정: 기록 공유·경품 결과 공유 링크도 친구가 유효 방문하면 일반 친구 초대와 동일하게 초대권 +1을 지급한다. 공유 버튼 클릭만으로 지급하지 않는다. 행사·초대자·방문자 관계의 중복 제한은 공유 유형 간에도 공통이며, 같은 친구가 기록/경품/일반 초대 링크를 번갈아 방문해도 중복 보상하지 않는다. 최대 보유 3장·쿨다운·자기초대 제한도 공통 적용한다.
- 현재 기록 공유가 prize_share로 표시되는 경로와 서버 지급 동작을 점검한다. 기록 공유·경품 결과 공유의 문구/유입 분류는 실제 의미대로 구분하고, 분류 변경이 보상 중복이나 기존 링크 단절을 만들지 않게 한다.
- 링크 미리보기 요청은 참여·공유 완료·추천 보상으로 처리하지 않는다.
- ‘예상 경쟁률’은 원문의 후보 아이디어다. 실제 산식·모집 인원·확률 근거가 없으면 운영 카피에서 제외한다. 참가자수÷잔여 경품을 개인 당첨확률로 쓰지 않는다.
- ‘Gemini로 만든 게임’과 ‘Antigravity를 활용’은 실제 제작 도구·승인 사실에 맞춰 구분한다. Google 공식 제작/보증으로 읽히게 쓰지 않는다.
2-2. 로딩
- 운영 주체와 참여 절차를 짧게 보여준다: 공룡 점프 → 복주머니 → 결과 확인.
- 익명 ID 복원/발급과 필요한 자산 준비는 1차 기능을 연결한다.
- 사용자 확정: 초기 로딩 화면은 2~3초간 브랜드·참여 흐름 연출을 보여준다. 일반 화면 전환마다 이 연출을 반복하지 않는다. 연출 시간과 실제 데이터/자산 준비 시간을 구분하고, 준비가 늦으면 오류 없이 대기·복구 상태로 이어간다.
- 상단: 'Google Student Ambassador'를 너무 크지 않게 표시한다.
- 중앙: 'Google AI로 만든 게임입니다'를 가장 먼저 크게 보여주고, 바로 아래에 '전국 대학생 한정 이벤트'를 표시한다. 게임 참여와 경품 자격을 혼동하지 않도록 '게임은 누구나 참여 가능 · 경품은 대학생 대상' 안내를 함께 제공한다.
- 전환: 메인 문구가 조금 작아지며 아래로 이동한 뒤 '게임하고' → '복주머니에서 복권 뽑고' → '긁으면 선물!' 순서로 보여주고, 마지막에 '최대 삼텐바이미!'를 강조한다. 짧은 시간에도 읽을 수 있게 전환 속도·잔상·배치를 실제 화면에서 확인한다.
- 하단: 우리 팀 Gemini 로고를 운영 주체 브랜딩으로 배치한다. 기존 이미지와 화면 애니메이션으로 우선 구현하고, 부족한 경우에만 이미지·영상 생성 추가를 검토한다.
- 위 경품 문구는 사용자 지정 Preview 시안이다. 실제 경품 확보·확률 확정으로 해석하지 않는다. 미당첨이 있는 구조에서 전원 당첨으로 오해하지 않도록 추첨 안내를 표시하고, 운영 공개 전 실제 경품과 문구를 대조한다.
- 실제 준비 완료와 로딩 연출 종료/다음 화면 노출 시점을 따로 기록하여 2~3초 연출을 서버 지연으로 집계하지 않는다. 모션 감소 설정에서는 같은 정보와 흐름을 정적인 연출로 제공한다.
- 실패 시 ‘다시 연결’ 등 복구 동선을 제공하며, 존재하지 않는 보안 인증·가입 검증 과정을 연출하지 않는다.
- 노출부터 다음 화면/마지막 관측까지 계측한다. 강제 종료의 정확한 이탈시각을 보장하는 문구는 금지한다.
2-3. 홈·시작·게임
- 한 줄 조작 안내와 시작 버튼을 제공한다. 현재 게임권·재도전 적립·복주머니 사용 상태를 서버 데이터로 표시한다.
- 게임은 초반 접근성·후반 긴장감을 살리는 원문 방향을 따른다. 난이도 변경은 실제 사전 테스트와 서버 검증을 함께 수행한다.
- 내 점수·최고점·순위를 표시한다. 플레이 중 순위는 조회 시점 값임을 알 수 있게 하고 지속 서버 요청으로 FPS를 낮추지 않는다.
- Antigravity 제작 배지는 실제 사용 사실과 승인에 맞는 경우에만 작은 위치에 배치한다.
- 정상 충돌·저장 중·검증 실패·통신 실패·재접속 상태를 구분한다. 잘못된 기록을 조용히 성공 처리하지 않는다.
2-4. 코인·하트·부활 — 클라이언트와 서버를 함께 변경
사용자 확정: 코인은 획득 시 점수 증가, 하트는 부활권 획득이다. 부활권 최대 보유량은 1개이며 한 판 총 부활 횟수를 1회로 제한하지 않는다.
- 최초에는 부활권 없이 시작하고 하트 획득으로 1개를 보유한다. 이미 보유한 동안 추가 하트를 획득해도 부활권을 쌓거나 별도 보너스를 임의 지급하지 않는다.
- 충돌 시 부활권이 있으면 1개를 소비해 같은 게임에서 자동 부활하고 점수를 이어간다. 부활 후 새 하트를 획득하면 다시 1개를 보유하고 다음 충돌 때 또 부활할 수 있다. 부활권이 없는 충돌은 정상 게임 종료다.
- 부활 순간에는 사용자가 살아났음을 느낄 수 있는 짧은 애니메이션/시각 효과를 구현한다. 제안: 하트 소비 표시 → 공룡 주변 빛/입자 또는 보호막 → 플레이 복귀. 이는 연출 초안이며 기존 디자인에 맞춰 검증한다. 화면을 오래 가리거나 조작을 불필요하게 막지 않고, 강한 반복 섬광은 피하며 모션 감소 대안을 제공한다.
- 코인당 점수·등장 빈도/위치·하트 등장 조건·부활 직후 무적시간·연출 중 게임 진행 여부는 구현 전 테스트용 수치안을 제시한다. 미정 수치를 사용자 확정값으로 기록하지 않는다. 부활 직후 같은 장애물에 즉시 재충돌하지 않도록 서버와 클라이언트가 같은 보호 규칙을 사용한다.
- 규칙은 게임 버전·seed에 연결한다. 서버도 코인/하트 생성·획득·보유 0/1·소비·반복 부활·무적 상태·최종 점수를 재현한다. 코인과 반복 부활에 따른 점수/최대 플레이 시간 검증 범위도 함께 점검한다.
- 에셋 원본: https://drive.google.com/drive/folders/14Ld1Fu6tdaA1Ik7Yaot3_O9oPRll6JW2 . 2026-09-26 사용자 추가 확정: https://drive.google.com/drive/folders/15nCZxtc-AFFk7nl4Q4bDtaNCv6VCqonz 의 Smile 이미지를 코인으로, Heart 이미지를 하트로 사용한다. Icons의 Light/Dark 원본을 확인했으며 기존 저장소의 같은 파일을 재사용한다. 원본 자료를 임의로 수정하지 않는다.
- 브라우저가 부활 플래그를 켠 것만으로 결과를 승인하지 않는다.
- 각 부활 충돌과 최종 게임 종료를 구분하고, 코인 획득·추가 점수·하트 획득·부활권 소비·부활 횟수 이벤트와 집계를 연결한다.
- 부활은 같은 게임 안에서의 동작이며 재도전권 소비·복주머니 추가 지급으로 바뀌지 않는다.
- 변경 전/후 기록의 랭킹 비교 가능 여부를 문서화하고 운영 도중 몰래 게임 규칙을 바꾸지 않는다.
- 부활을 구현하지 못했다면 2차 보고에 기능 보류로 표시하고 화면에 약속하지 않는다.
2-5. 게임 결과·랭킹
- 내 점수·최고점·현재 순위·TOP3 경품 안내를 구분한다.
- ‘현재 3위까지 ○점’은 서버 점수 차이를 사용하고 동점/이미 TOP3/참가자 부족 상태도 처리한다. ○초만 더 하면 돈을 받는다는 확정 표현은 쓰지 않는다.
- TOP3 진입자에게 이름·연락처·학교 입력을 요청한다. ‘현재 TOP3 / 최종 지급은 이벤트 종료 시점 기준’ 문구를 같이 표시한다.
- 기존 등록 정보가 있으면 중복 입력을 요구하지 않는다. 순위 하락·다시 진입·통신 실패·미등록 복귀 상태를 처리한다.
- 등록 요청이 복주머니 수령을 불필요하게 막지 않도록 복귀 동선을 제안한다. 최종 등록기한·미등록 처리 규칙은 3차 정책에 따른다.
2-6. 재도전 바이럴·재방문
- ‘친구에게 공유하고 재도전권 받기’와 ‘복주머니 열기’를 모두 제공한다. 공유하지 않아도 복주머니 진행이 가능해야 한다.
- 친구 유효 방문 기준은 3초 활성+클릭/터치이며 게임 완료 조건을 다시 넣지 않는다.
- ‘친구가 방문하면 자동 적립 / 먼저 복주머니를 열고 나중에 재도전 가능 / 추가 추첨 없음’을 설명한다.
- 남은 재도전권·지급/사용/환급량·초대 현황·적립 완료·쿨다운·새 방문 대기를 구별한다. 기본권은 초대권 잔액과 별도다.
- 초대권 최대 보유량은 3장이며 새 초대 보상으로 잔액이 3장이 되는 순간 10시간 추가 적립 대기를 시작한다. 대기 중 사용은 가능하지만 잔액이 줄어도 새 적립은 금지한다. 누적 지급 3회 제한은 두지 않는다.
- 새 쿨다운 안내는 쿨다운 설정마다 한 번 표시한다. 10시간 뒤 남은 게임권은 유지하고 새 유효 방문으로 빈자리에 적립한다. 다시 3장이 되면 새 10시간이 시작되며 자동 충전·방문 이월·장애 환급에 의한 재시작은 없다.
- 브라우저가 다시 활성화되거나 재접속할 때 서버에서 잔액을 갱신한다. 일반 참가자 전체에 Realtime을 추가할 필요는 없다.
- 동일 브라우저·쿠키 유지 조건으로 기록이 복원됨을 도움말에 명시한다. 모든 기기 자동 동기화를 약속하지 않는다.
2-7. 복주머니·복권 긁기
- 첫 정상 플레이 후 3개 주머니 선택 → 복권 등장 → 긁기 → 결과를 구현한다.
- 이미 복주머니를 사용한 참가자는 새 선택 대신 기존 결과/수령 상태로 이동한다. 랭킹 재도전은 별도 가능하다.
- 서버 확정 결과를 연출로 보여줄 뿐 다시 긁거나 주머니를 바꿔 새 결과를 얻을 수 없어야 한다.
- 중도 이탈·재접속 시 선택/긁기/결과 확인 상태를 복구한다.
- 접근성 보완 제안: 긁기 조작이 어려운 사람에게 같은 결과를 확인하는 보조 버튼을 제공한다. 이는 추가 추첨이나 자격 우회가 아니다.
- 각 단계 진입·클릭·완료·실제 결과 노출·활성 체류를 연결한다. 서버 추첨 시점과 화면 노출 시점은 구분한다.
2-8. 당첨·수령·미당첨
- 당첨: 축하 → 재학생 확인 안내 → 이름/연락처/학교 입력 → 운영팀 확인·개별 연락·수동 지급 안내.
- 개인정보 설명과 필수 동의 등은 D12 확정 내용으로 연결하고 테스트에서는 합성값만 받는다.
- 미당첨: 짧은 안내 → ‘경품과 별개로, 대학생 혜택도 챙겨가세요’ → Gemini 안내.
- 대화 보완에 따라 당첨자도 수령 접수 후 Gemini 안내를 볼 수 있게 한다. 이미 얻은 경품의 지급을 외부 가입으로 새롭게 제한하지 않는다.
- 빈 입력/잘못된 형식/서버 오류에서 입력 내용을 잃거나 폼이 먼저 닫히지 않게 한다.
- 수령정보 접수와 연락 완료/실제 전달 완료를 구별해 표시한다. 재학생 증빙의 제출 방법은 미정이면 자동 업로드 기능을 확정하지 않는다.
2-9. Gemini 혜택·활용 가이드
- 주요 버튼은 승인된 공식 혜택 페이지로 이동한다. 링크 복사, 카카오톡/일반 공유, 외부 브라우저에서 여는 방법은 보조 동선으로 제공한다.
- 특정 브라우저 자동 실행을 모든 기기에서 보장하지 않는다. 지원 안 되는 경우 복사/안내로 대체한다.
- 혜택명·기간·대상·가격·조건은 3차 검증 전 placeholder로 둔다. ‘3분 완료’, ‘학교 인증만 필요’, ‘100% 제공’을 확인 없이 사용하지 않는다.
- 이용 여부 질문을 추가하지 않고 ‘이미 사용 중이라면’ 문구와 가이드 카드를 바로 보여준다. 미가입자도 가이드를 볼 수 있게 한다.
- 우선 콘텐츠는 원문의 ‘4년 평균 4.26, 실제로 쓰는 Gemini 비밀 노트’와 취업사진 가이드다. GPA·활용 사례·사진 예시는 실제 자료/사용자 승인에 근거한다. 결과물·체험담을 지어내지 않는다.
- 공부/과제·취업·발표/PPT 등 추가 카드는 실제 콘텐츠가 있는 경우 연결한다.
- 사용자가 지정한 Notion 연결 대상은 다음 두 페이지다. 실제 제목·내용을 확인해 해당 가이드 카드와 연결하며 어떤 페이지가 공부/취업사진인지 추측하지 않는다.
  - https://app.notion.com/p/3d41ef9d40cd803f9e56da74a08c695f?source=copy_link
  - https://app.notion.com/p/3d01ef9d40cd80a798f1c353b8b4311d?source=copy_link
- 2026-09-25 브라우저 재확인에서 두 페이지의 본문 열람을 확인했다. 첫 번째는 ‘제미나이 노트북’, 두 번째는 ‘취업사진 프롬프트’다. 연결 도구의 조회 실패와 일반 웹 열람을 구분한다. 링크 연결 요청을 원문 편집·공개 권한 변경 승인으로 확대하지 않는다.
- Notion의 혜택 CTA에도 공식 링크를 넣는다. 중간 추적 주소는 승인된 경우만 사용하고, 미허용이면 직접 링크와 측정 불가 표시를 사용한다.
- 외부 콘텐츠 이동은 선택 동선이며, 혜택을 받으려면 노트를 먼저 읽어야 하는 구조로 바꾸지 않는다.
3. 실제 화면 계측 완료
- 1차 이벤트 계약을 기준으로 노출·CTA·선택·긁기·등록·복사·공유 시도를 실제 컴포넌트에 연결한다.
- 새 버튼이나 부활을 추가하면 이벤트 사전·관리자 집계·테스트도 함께 수정한다.
- 가상 UI에만 이벤트가 있고 실제 화면에는 없는 상태로 끝내지 않는다.
- 로딩 0–1/1–2/2–3초, 게임 시간/단계, 복주머니·긁기 단계, 미당첨 결과→CTA 전/후의 관측 결과가 집계되는지 확인한다.
- 선택적 공유/재도전을 건너뛰는 것은 전체 이탈로 세지 않는다. 복주머니→재도전→다시 결과처럼 반복/분기하는 동선을 하나의 일직선 퍼널로 억지 계산하지 않는다.
- Notion 이동 클릭과 본문 열람, 링크 클릭과 가입, 공유창 호출과 실제 전달은 계속 구분한다.
4. 검증·산출물
검증
- 신규, 재방문, 권리 없음, 권리 적립, 쿨다운, TOP3/비TOP3, 당첨/미당첨, 이미 추첨함, 수령 완료 상태를 각각 시험한다.
- 카카오톡/인스타 인앱·iPhone Safari·안드로이드·데스크톱 중 실제 확인한 범위와 에뮬레이션을 구분한다.
- 반응형 잘림·터치·뒤로가기·새로고침·중간 이탈·동시 탭·통신 끊김을 점검한다.
- 게임 프레임·입력·반복 플레이 후 메모리/이벤트 중복을 확인한다. 1차 HTTP 부하 결과를 모바일 FPS 증명으로 쓰지 않는다.
- 부활/난이도 변경 후 서버 재현·랭킹/보상 정합성 테스트를 반복한다.
- 코인 획득 점수 일치, 하트 추가 획득 시 보유 1개 상한, 부활권 소비, 같은 판에서 하트 재획득 후 두 번째 이상 부활, 부활권 없는 최종 충돌, 무적시간 경계·중복 입력·위조 로그 거절을 검사한다. 부활 연출이 결과 재현·조작 반응·모바일 FPS를 깨뜨리지 않는지 확인한다.
- 기록/경품/일반 초대 각각의 유효 방문 보상, 유형을 바꾼 동일 친구의 중복 보상 차단, 공유 유형별 집계를 검증한다. 로딩 연출 2~3초·준비 지연·실패 복구·중앙 로고·Notion 두 링크의 실제 접근 상태를 확인한다.
- 최종 화면을 연결한 상태에서 지표 집계 E2E와 대표 100~200 VU 혼합 부하를 격리 환경에서 재실행한다. 1차처럼 사전 비용·상한을 확인하고 승인 없이 확대하지 않는다.
- 사전 사용자 테스트는 테스트 경품으로 진행하는 별도 운영 제안이다. 실제 참가자 모집·연락은 요청 없이 실행하지 않는다.
