# Phase 3 최종 부하 테스트 보고서 — 2026-09-29

## 결론

수정된 Preview에서 100명 단계 300개 흐름과 200명 동시 시작 단계 200개 흐름, 총 500개 흐름이 오류 없이 완료됐다. 최종 실행은 API 5,502회에서 5xx·429·timeout·예상 밖 실패가 0건이었다.

최대 동시 작업자 200명 조건에서 기능 완결성은 확인했다. 응답 속도는 목표보다 느렸다. 최종 실행의 추첨 생성 p95는 4.56초였고 추첨 조회·스크래치 완료도 p95 3초를 넘었다. 따라서 “200명에서도 동작한다”는 근거로 사용할 수 있지만 “200명에서도 빠르다”거나 “일반 응답 p95 1초를 만족한다”고 표현하면 안 된다.

## 대상과 안전 조건

- 환경: 별도 Vercel Preview + Supabase `dino_dev` 합성 캠페인
- 게임 규칙: 2.1.0
- 게임권: 무제한 OFF, 참가자별 실제 최초 1장·100점 이하 환급 경로 사용
- 추첨: 합성 5,000칸, 실제 경품 77칸 구조를 복제하고 나머지 4,923칸은 혜택 결과
- 참가자: 합성 5,000명 중 실행별 새 참가자만 순서대로 사용
- 제외: 본행사 `dino_prod`, 실제 카카오 완료 웹훅, 수령정보 쓰기, 실제 개인정보
- 누적 상한: HTTP 7,000회, 부하 실행 예약 390초

당시 77개 풀 정의는 `docs/evidence/phase3-load-manifest-20260929.json`으로 고정했다. 이후 실제 상품 수량 변경과 이 시험 결과를 섞지 않는다.

## 실행 이력

### 1. 최초 실행 — 서버 연결 대기 실패

| 항목 | 결과 |
| --- | ---: |
| 실제 경과 | 11.52초 |
| 러너 API | 460회 |
| 준비 조회 포함 누적 | 462회 |
| 완료 흐름 | 0회 |
| 예상 밖 실패 | 39회 |
| 503 | 39회 |

100명 단계에서 게임 생성·시작은 각각 100건 성공했지만 게임 완료 27건, 추첨 생성 2건, 추첨 조회 8건, 스크래치 2건이 503으로 종료됐다. 200명 단계는 시작하지 않았다. Vercel 로그에서 DB 연결 풀 대기 3초 만료가 확인됐다.

행사 행 잠금을 참가자별 게임 완료 트랜잭션 전체에서 배타적으로 잡던 구조를 공유 잠금으로 좁혔고, DB 연결 대기를 5초로 늘렸다. 참가자 세션 잠금과 관리자 마감·확정 배타 잠금은 유지했다.

### 2. 수정 확인 실행 — 하네스 이벤트 계약 오류

| 항목 | 결과 |
| --- | ---: |
| 실제 경과 | 6.31초 |
| 새 API | 356회 |
| 누적 API | 818회 |
| HTTP 5xx·429·timeout | 0회 |
| 완료 흐름 | 0회 |

서버 요청은 정상 처리됐지만 러너가 자체 이벤트에 허용되지 않은 분석 차원을 넣었다. 이벤트 API가 일부 이벤트를 거절했고, 러너의 `accepted=2` 검사가 의도대로 실행을 중단했다.

이 결과는 서버 부하 실패로 계산하지 않았으며 성공으로도 계산하지 않았다. 하네스 결함으로 별도 보존했다. 이벤트 값을 서버 허용 목록에 맞춘 뒤 실제 이벤트 처리 함수에서 2건 모두 수락되는 회귀 검사를 추가했다.

- 완료 흐름 500/500
- API 상태: 조회 200, 생성 201, 이벤트 묶음 202로 전부 기대 상태

## 확인한 범위

- 최대 100명 단계에서 반복 흐름 300개 완료
- 200명 동시 시작에서 각 작업자 1개씩, 총 200개 완결 흐름 완료
- 게임 2.1.0 검증 및 100점 이하 게임권 환급 경로
- 비복원 추첨 생성·결과 조회·스크래치 완료
- 랭킹·초대·수령함 조회
- 자체 분석 이벤트 2건 저장 계약
- 서버 오류·rate limit·timeout 없이 전체 완료

종료 후 읽기 전용 DB 대조 결과는 다음과 같다.

- 완료·검증 게임 500건
- 추첨 500건: 합성 상품 5건, 혜택 495건
- 추첨권 차감 500건, 배정 슬롯 500개
- 중복 사용된 재고 0건
- 100점 이하 환급 500건

이 대조 근거는 `docs/evidence/phase3-load-reconciliation-20260929.json`에 있다.

## 확인하지 않은 범위

- 200명이 30초 동안 계속 반복 요청하는 지속 부하
- 5,000명 동시 접속
- 모바일 화면 FPS, 터치 반응, 스테이지 전환 애니메이션
- 실제 카카오톡 전송·완료 웹훅
- 경품 수령정보 입력·제출 쓰기
- 실제 본행사 개인정보·경품 재고 처리
- 장시간 운영 중 메모리 누수·콜드 스타트·지역별 네트워크 편차
- 100점을 초과한 게임과 그에 따른 게임권 차감. 이번 500건은 모두 100점 이하였고 환급됐다.
- 코인 획득과 부활 2회를 함께 수행한 게임 경로. 이번 실행에서는 해당 게임이 0건이었다.

따라서 이번 원격 부하 결과를 고득점 게임권 차감이나 코인·다중 부활 경로까지 검증한 근거로 사용하지 않는다. 이 항목들은 별도 기능 회귀와 실제 플레이 검증 범위다.
