# 공룡 점프 — GA4 보조 분석 도입 기획안

- 작성일: 2026-09-29
- 상태: 2026-09-29 베타 연결·실제 수집 검증 완료. 운영 속성 준비, 본행사 수집 전환 전.
- 실제 설정과 검증 기록: [관측 도구 연결 기록](observability-setup.md)
- 대상: 공룡 점프 웹사이트
- 운영 방식: 기존 관리자 통계와 GA4 병행

## 1. 목적

다음 질문에 답할 수 있도록 방문·참여·전환을 분석한다.

1. 어떤 홍보 채널에서 사람들이 들어오는가?
2. 로딩·튜토리얼·게임·복주머니 중 어디에서 진행을 멈추는가?
3. 친구 공유가 새로운 방문과 게임 참여로 이어지는가?
4. Gemini 혜택과 활용 가이드 중 어떤 콘텐츠에 반응하는가?
5. 특정 기기·브라우저에서 참여율이 떨어지는가?

## 2. 기존 통계와 GA4의 역할

| 구분 | 담당 범위 | 판단 기준 |
| --- | --- | --- |
| 자체 관리자·Supabase | 서버 승인 게임 기록, 점수·순위, 카카오 전송 확인, 게임권·뽑기권, 당첨·수령 접수 | 행사 운영과 권리·경품 지급의 기준 |
| GA4 | 유입 채널, 신규·재방문, 기기·브라우저, 화면 이동, 퍼널 전환·이탈 | 홍보 성과와 UX 개선 분석 |
| Vercel·Supabase 운영 지표 | 응답 지연, 서버 오류, DB 연결·자원 사용 | 장애·혼잡 대응 |

GA4 수집 여부는 게임 참여·당첨·접수 성공 조건으로 사용하지 않는다. 실제 가입·Gemini 혜택 등록 완료는 Google 측의 별도 확인 수단이 없으므로 측정 완료로 표현하지 않는다.

## 3. 계정과 측정 범위

### 기본 구성

- 사용자 소유 Google 계정에 공룡 점프 전용 GA4 속성을 구성한다.
- 표시 시간대는 `Asia/Seoul`로 맞춘다.
- 기존 속성·태그가 있다면 먼저 확인해 중복 설치를 방지한다.
- 운영 수집은 승인된 운영 환경·도메인에서만 활성화한다.
- 로컬·Preview·부하 테스트는 운영 속성으로 전송하지 않는다.
- 사전 검증은 별도 테스트 속성을 사용한다. 같은 속성의 스트림만 나누는 것으로 운영 데이터 분리를 대신하지 않는다.

### 연결 방식

- 기존 행동 이벤트 수집 지점에 GA4 전송 연결부를 추가한다.
- 초기 접속·로딩 관측은 DB 참가자 생성 성공을 기다리지 않도록 설계한다.
- 화면 이동은 가상 페이지 조회로 기록한다.
- 자동 페이지 조회와 수동 전송 중 담당 방식을 명확히 정해 한 번의 진입이 중복 집계되지 않도록 한다.
- GA4 전송은 비동기로 처리하며 게임 시작·종료·추첨·접수 응답을 기다리게 하지 않는다.
- GA4 차단·연결 실패 시에도 서비스 기능은 정상 동작해야 한다.

## 4. 퍼널 설계

선택 기능과 반복 참여가 있으므로 전체 흐름을 하나의 필수 경로로 강제하지 않는다.

| 퍼널 | 분석 단계 | 분석 목적 |
| --- | --- | --- |
| 게임 참여 | 접속 → 로딩 완료 → 홈 → 튜토리얼 → 게임 시작 → 게임 완료 | 진입·설명·플레이 단계의 손실 파악 |
| 복주머니 | 게임 완료 → 복주머니 진입 → 주머니 선택 → 긁기 → 결과 확인 | 추첨 화면별 진행률 파악 |
| 경품 수령 | 수령 대상 양식 노출 → 입력 시작 → 임시 저장 → 공유 시도 → 접수 완료 | 입력·공유 단계의 마찰 파악 |
| 친구 초대·재도전 | 공유 CTA 노출 → 공유 시도 / 초대 링크 방문 → 게임 시작·완료 | 공유 유도와 초대 유입의 참여 효과 파악 |
| Gemini 전환 | 혜택 화면 → CTA 실제 노출 → 공식 링크 클릭 | 혜택 페이지 이동률 파악 |

### 퍼널 해석 기준

- 경품 수령 퍼널의 분모는 수령 대상자로 한정한다.
- 첫 게임 참여와 재도전은 구분한다.
- 복주머니 첫 뽑기와 추가 뽑기는 회차로 구분한다.
- 친구 초대의 발신자와 수신자는 서로 다른 사람이다. 하나의 사용자 퍼널로 연결하지 않고, 공유 측·유입 측을 별도로 보고한다.
- 공유 버튼 클릭·공유창 열림은 실제 카카오 전송 성공과 구분한다.
- 실제 카카오 전송·보상 적립은 서버 웹훅과 원장 기록을 기준으로 확인한다.
- 단계별 관측 시간·분모·진행 중 제외 기준을 보고서에 명시한다. GA4 기본 이탈률을 자체 화면별 추정 이탈률과 동일한 지표로 취급하지 않는다.
- 가이드 열기처럼 선택 기능을 건너뛴 행동을 행사 전체 이탈로 해석하지 않는다.

## 5. 수집할 핵심 행동

아래 명칭은 분석 목적을 나타낸다. 실제 이벤트 이름은 기존 코드와 대응표를 작성한 뒤 고정한다.

| 행동 | 기록 시점 | 주요 분류 정보 |
| --- | --- | --- |
| 화면 진입 | 해당 화면이 표시된 시점 | 화면명, 이전 화면 |
| 로딩 완료 | 필요한 준비와 로딩 화면이 완료된 시점 | 화면명 |
| 튜토리얼 진행·건너뛰기 | 슬라이드 이동 또는 건너뛰기 | 슬라이드, 행동 |
| 게임 시작 | 서버에서 게임 시작을 승인한 시점 | 첫 게임·재도전, 게임 버전 |
| 게임 완료 | 서버가 게임 결과를 승인한 시점 | 점수, 플레이 시간, 게임 버전 |
| 주머니 선택·긁기 | 사용자의 선택·긁기 시작 | 뽑기 회차, 단계 |
| 복주머니 결과 노출 | 결과가 화면에 실제 표시된 시점 | 회차, 실제 상품·Gemini 혜택 구분 |
| 수령 입력 시작·임시 저장 | 양식 조작 시작·서버 임시 저장 성공 | 복주머니·랭킹 수령 구분 |
| 수령 접수 완료 | 최종 접수 성공을 서버에서 확인한 시점 | 수령 유형 |
| 공유 CTA 노출·공유 시도 | 버튼 노출·사용자가 공유를 시도한 시점 | 게임 재도전·추가 뽑기·경품 자랑·혜택·가이드, 버튼 위치, 공유 수단 |
| Gemini CTA 노출·클릭 | CTA 실제 노출·외부 링크 클릭 | 버튼 위치 |
| 가이드 열기·복사·공유 | 각 행동 발생 시점 | 공부법·취업사진, 행동 |

### 성공 이벤트의 기준

- 버튼 클릭과 서버 처리 성공은 다른 이벤트로 취급한다.
- 결과 화면 재방문은 화면 조회로 기록하되, 새로운 게임 완료·추첨·접수 성공으로 기록하지 않는다.
- GA4에 실제 카카오 전송 확인 이벤트를 추가한다면 서버 확인을 근거로 해야 한다. 브라우저 복귀 때만 전송하는 방식의 누락 가능성은 따로 표시한다.
- 점프·프레임·매초 점수 변경처럼 빈번한 게임 동작은 이번 GA4 범위에서 제외한다.

## 6. 유입 채널 관리

홍보 링크에 일관된 UTM 값을 붙여 비교한다.

| 사용처 | source 예시 | medium 예시 |
| --- | --- | --- |
| 카카오 친구 초대 | `kakao` | `referral` |
| 인스타그램 프로필·스토리 | `instagram` | `social` |
| 학교 커뮤니티 | `campus_community` | `community` |
| 포스터 QR | `campus_poster` | `qr` |

- `campaign`은 행사 단위로 통일한다.
- 프로필·스토리·포스터 위치 등 소재 구분에는 `content`를 사용한다.
- 기존 초대 보상용 파라미터는 서비스에서 계속 처리한다.
- GA4로 보내는 주소에서는 불필요한 개인별 초대 코드·공유 식별값·민감한 쿼리를 제거한다.
- 출처를 확인하지 못한 방문을 임의로 카카오·인스타그램에 배정하지 않는다.

## 7. 보고서 구성

### A. 전체 현황

- 사용자·세션·화면 조회
- 신규·재방문
- 게임 시작·완료
- 복주머니 결과 확인
- 수령 접수 완료
- Gemini 공식 링크 클릭

### B. 단계별 전환·이탈

- 4절의 목적별 퍼널 5개
- 각 단계 진입 인원·후속 진행 인원·전환율
- 첫 참여·반복 참여 구분
- 조회 기간과 단계 간 허용 시간을 표시

### C. 홍보 성과

- 채널·소재별 방문
- 채널별 게임 시작·완료율
- 채널별 Gemini 클릭률
- 초대 링크 유입의 참여율

### D. 기기별 UX

- 모바일·PC 비교
- Safari·Chrome 등 브라우저 비교
- 기기·브라우저별 로딩 이후 참여율과 게임 완료율

## 8. 개인정보와 데이터 관리

- 이름·전화번호·학교 입력값·주소·대학생 인증 자료는 GA4로 보내지 않는다.
- 인증 쿠키·토큰·비밀키를 이벤트나 URL에 포함하지 않는다.
- 수령 양식의 자유 입력값을 자동 수집하지 않는다.
- 1차 연결에서는 자체 참가자 ID를 GA4 User-ID로 연동하지 않고, 집계 수준에서 비교한다.
- 이벤트 파라미터는 허용 목록으로 관리한다.
- 분석용 쿠키 안내·동의 처리와 GA4 보관기간을 설정 단계에서 확정한다.
- 수령 정보의 ‘경품 지급 완료 후 30일 이내 삭제’와 GA4 분석 데이터의 보관 설정은 별도로 문서화한다.

## 9. 숫자 비교 시 주의사항

- GA4와 자체 통계는 식별·세션·관측·처리 시점이 달라 수치가 완전히 같지 않을 수 있다.
- 브라우저 차단·동의 상태·전송 실패에 따른 누락을 고려한다.
- 화면 노출·공유 시도는 관측값이다. 실제 권리 지급·당첨·접수 기록은 서버 자료로 확인한다.
- 두 도구가 같은 이벤트 발생 코드를 사용하면 같은 누락이 양쪽에 생길 수 있다. 서버 기록과 실제 동작을 함께 대조한다.
- 일반 GA4 보고서의 반영 지연을 즉각적인 서비스 장애로 판단하지 않는다.
- Gemini 외부 링크 클릭을 실제 학생 인증·가입·혜택 등록 완료로 표현하지 않는다.

## 10. 작업 순서

1. 기존 GA4 계정·속성·태그와 사용할 소유 계정을 확인한다.
2. 운영·테스트 속성, 시간대, 데이터 관리 설정을 준비한다.
3. 기존 이벤트와 GA4 이벤트의 대응표·분모·성공 기준을 확정한다.
4. 화면 조회와 핵심 행동의 비동기 전송을 연결한다.
5. 운영·테스트 분리, 주소 정리, 중복 전송 방지를 적용한다.
6. 퍼널·채널·기기 보고서를 구성한다.
7. DebugView와 실제 게임 흐름으로 수집을 검증한다.
8. 메인 개발 작업에 통합해 배포하고 운영 이벤트를 확인한다.

## 11. 완료 기준

체크한 항목은 코드와 자동 검사로 확인한 범위다. 실제 베타 브라우저에서는 동의·거절·철회, 화면 이동, 테스트 속성 DebugView 수신을 추가 확인했다. 모든 게임·추첨·접수 경로의 GA4 수신과 서버 기록 대조까지 확인했다는 뜻은 아니다.

- [x] 화면 한 번 이동 시 해당 화면 조회가 한 번 기록된다.
- [x] 첫 페이지 조회가 자동·수동 전송으로 중복되지 않는다.
- [x] 로딩 관측이 참가자 생성 성공에 종속되지 않는다.
- [x] 게임 완료와 수령 접수 성공은 서버 성공 확인 후 기록된다.
- [x] 새로고침·결과 화면 재방문으로 성공 이벤트가 추가 생성되지 않는다.
- [x] 공유 취소·공유창 열기를 실제 전송 성공으로 기록하지 않는다.
- [x] 복주머니·게임·경품 자랑·혜택·가이드 공유 목적이 구분된다.
- [ ] 개인정보·인증값이 GA4 요청에 포함되지 않는다.
- [x] 로컬·베타·부하 테스트 이벤트가 운영 속성에 섞이지 않는다.
- [x] GA4를 차단하거나 전송에 실패해도 게임·추첨·접수가 정상 동작한다.
- [ ] 주요 이벤트를 서버 기록과 대조하고 차이의 원인을 설명할 수 있다.
- [ ] 보고서에 분모·시간 범위·관측 한계가 표시된다.
