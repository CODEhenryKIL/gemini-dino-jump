## 우선 수정·대응할 사항

### A-01 · P1 · 일시적인 408/429 응답 때문에 미전송 게임 결과가 삭제됨

**위치:** `public/js/views/game_view.js:112–149`, 핵심 `143–146`.

종료 결과와 재전송 키를 브라우저에 보관한 뒤 복구하는 과정에서, 코드가 500 미만의 모든 HTTP 오류를 영구 실패로 분류한다. 세션 조회 또는 종료 재전송이 일시적인 요청 제한(429)이나 시간 초과(408)를 만나도 보관된 결과를 삭제한다. 다음 진입에서 미완료 게임 무효·환급 경로로 넘어가면 실제 플레이 점수를 복원할 기회가 사라진다.

**재현:** getSession을 429로 실패시킨 독립 스크립트를 두 검토자가 확인했다.

```json
{"result":false,"pendingFinishStillStored":false,"refreshes":1}
```

- 증거: `/private/tmp/dino-recover-429-repro.cjs`.
- 같은 파일의 장애 복구 로직(`633–639`)과 분석 전송은 408/429를 재시도 대상으로 다룬다.
- 수정: 네트워크 오류·408·429·5xx에서는 종료 payload와 동일한 idempotency key를 보존한다. 서버가 확정적으로 거부한 상태에서만 삭제한다.
- 완료 기준: 세션 조회와 종료 재전송 각각의 408/429 → 복구 성공 회귀 테스트. 오래된 응답이 새 게임 데이터를 지우지 않는 기존 보호도 유지한다.

### A-02 · P1 · 자동 플레이 기록도 실제 경품 랭킹에 들어갈 수 있음

**위치:** `server/operations.py:437–439,508–550`, `server/game_verifier_v2.py:248–272`, `public/js/game/simulation.js`, `tests/js_v2_fixture_runner.cjs:11–25`.

서버 검증은 제출한 점수가 게임 물리 규칙과 일치하는지 확인한다. 사람이 직접 조작했는지는 확인하지 않는다. 클라이언트에 제공되는 seed와 시뮬레이터로 화면을 렌더링하지 않고 점프 기록을 만들 수 있다.

**확인한 범위:** 저장소의 자동 플레이 테스트 코드로 2.1.0/seed 4에서 797점·4547 tick·66회 점프를 생성했고, 실제 점수 검증 함수가 VERIFIED를 반환했다. 서버의 경과시간 검사를 통과하려면 약 75.8초를 기다려야 하므로 즉시 점수를 올리는 공격은 아니다. 원격 API에 이 기록을 제출하거나 실제 순위를 바꾸지는 않았다. 현재 TOP3를 이겼다는 의미도 아니다.

**영향:** 자동으로 만든 유효 기록도 랭킹 후보로 들어갈 수 있어, 실제 경품 지급 전 부정 플레이 검토가 필요하다. 이 항목은 물리 검증 오류보다는 경품 이벤트의 부정 참여 대응에 관한 설계 위험이다.

- 우선 대응: 최종 TOP3의 플레이 기록을 운영자가 검토하고 검토 결과를 남긴 후 확정·지급하도록 한다. 자격 확인(재학생 여부)과 플레이 정당성 확인은 별개다.
- 추가 대응: 비정상 반복·동일 입력 패턴·세션 활동 등 탐지 신호를 검토한다. 불확실한 신호 하나로 정상 사용자를 자동 탈락시키지 않는다.
- 실시간 서버 challenge를 도입하더라도 자동 플레이를 완전히 막는다고 표현하지 않는다. seed 숨기기나 프론트 코드 난독화만으로 해결되지 않는다.
- 완료 기준: 의심 기록의 보류·검토·판정·감사 기록 경로와 최종 확정 전 확인 절차를 정한다. “VERIFIED = 사람이 플레이함”으로 운영하지 않는다.

### A-03 · P2 · 행사가 끝나거나 일시 중단돼도 열린 화면에 게임 시작 버튼이 남음

**위치:** `public/js/app.js:106–123,193–229`, `public/js/views/home.js:60–80`, `public/js/views/result_view.js:110–115`.

config는 최초 로딩 때만 가져오고, 앱 복귀/상태 갱신은 참가자 상태만 다시 읽는다. 홈·재도전 버튼은 오래된 status를 사용하며 opens_at/closes_at으로 시간 경계를 계산하지 않는다. 예정 종료 시간이 지나도 DB status 자체가 ACTIVE이면 새로고침 후에도 같은 문제가 발생할 수 있다.

**영향:** 사용자가 튜토리얼을 거친 다음 서버에서 행사 종료 오류를 받고, 홈에서 다시 같은 과정을 반복할 수 있다. 서버의 마감 검사는 작동하므로 종료 후 기록이 허용된다는 뜻은 아니다.

- 수정: 서버 기준의 유효 행사 상태/시간을 갱신하고 홈·결과·공유·추첨 CTA에 일관되게 반영한다.
- 완료 기준: 열린 탭의 PAUSED/ENDED 전환, 예약 시작·종료 경계, 백그라운드 복귀를 테스트한다.

### A-04 · P2 · 응답이 오지 않는 요청에서 로딩을 끝낼 시간 제한이 없음

**위치:** `public/js/api.js:17–31`, `public/js/app.js:106–154`.

API fetch와 응답 본문 읽기에 애플리케이션 차원의 제한 시간이 없다. 초기화는 이 요청들과 이미지/폰트 준비 Promise가 모두 끝나야 완료된다. 모바일 네트워크 전환 등으로 연결이 오래 pending이면 오류 처리와 “다시 연결” 버튼까지 도달하지 못한다. 선택 자산도 현재 초기 로딩 대기에 포함된다.

- 수정: 필수 초기 요청·필수 자산의 대기 상한과 재시도 경로를 둔다. 선택 자산은 전체 진입을 계속 막지 않도록 한다.
- 완료 기준: 영구 pending을 흉내 낸 요청 → 제한 시간 오류 → 재시도 성공, 늦은 이전 응답 무시를 검증한다.
- 사용자의 이전 접속 불가 현상을 이번 코드만으로 같은 원인이라고 단정하지 않는다.

### A-05 · P2 · 개인정보 입력·동의 화면까지 확대를 막는 viewport 설정

**위치:** `public/index.html:5`.

`maximum-scale=1.0,user-scalable=no`가 게임 외 모든 화면에도 적용된다. 이 설정을 따르는 모바일 WebView에서는 작은 동의문과 안내를 확대하기 어렵다. 수동 테스트의 200% 확대 요구와도 맞지 않는다.

- 수정: 전체 페이지의 확대 제한을 해제하고, 점프 버튼의 선택·길게 누르기 제한은 그 버튼 영역에만 유지한다.
- 완료 기준: 모바일 200% 확대에서 동의·연락처 입력·제출 버튼에 접근할 수 있는지 확인한다. 이번 감사에서 물리 단말로 다시 확인하지는 않았다.

### A-06 · P2 · 운영 지침에 구현 전 설명과 구현 후 설명이 동시에 남음

**위치:** `docs/phase3-runbook.md:47,54,62–70` vs `77–90`.

앞부분은 “dense_rank 공동 순위, 먼저 달성한 순서 미구현”, “production 미지원”, “DRAFT 스냅샷만 가능”이라고 설명한다. 뒤의 추가 항목과 현재 코드는 먼저 달성한 순서, production guard, 최종 확정·지급 연결을 구현한 상태다.

**영향:** 행사 마감 담당자가 오래된 절차를 따라 최종 순위 확정을 지연하거나 다른 판단을 할 수 있다.

- 수정: 현재 적용되는 단일 운영 절차로 합치고 과거 상태 설명은 이력으로 이동한다.
- 완료 기준: 마감 → 대기 → 새 스냅샷 → 검토·확정 → 자격 확인·지급 절차를 실제 관리자 화면과 대조한다.

## 본행사 오픈 준비 상태

`python scripts/phase3_preflight.py --require-launch-ready`는 **설정 오류 0개 / 미완료 9개로 exit 1**이다. 의도대로 오픈 준비 완료 판정을 막는다.

미완료 항목:

1. manifest 상태 APPROVED
2. 운영 환경 승인
3. 혜택·브랜드 안내 승인
4. 공개 오픈 승인
5. 운영 DB·백업 증거
6. 실제 기기 QA 증거
7. 최종 부하 테스트 증거 — 사용자 요청으로 보류
8. Notion·Gemini 링크의 비로그인 접근/혜택 확인
9. 롤백 리허설 증거

원격에는 아직 `dino_prod`가 없다. 현재 베타를 본행사로 오해하면 안 된다. 새 유료 프로젝트를 만들 필요 없이 합의한 기존 프로젝트 내 운영 영역 준비가 남아 있다. 테스트 기록은 삭제하지 않았다.

확정 설정은 시작 2026-09-29 19:00 KST, 게임·추첨 종료 2026-10-03 00:00 KST 미만, 수령 접수 종료 2026-10-04 00:00 KST 미만이다. 상품 수량은 복주머니 77개/랭킹 3개, 총 1,599,000원이며 실제 구매 완료의 증명은 아니다.

### 아직 확인되지 않은 사용자 흐름

- 수령용 “나에게 보내기”는 서버 로직·테스트에서 허용됐지만, 변경 후 실제 휴대폰에서 최종 접수까지의 확인은 기존 접수 완료 상태 때문에 남아 있다.
