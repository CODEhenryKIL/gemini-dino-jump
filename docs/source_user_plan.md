# 사용자 제공 기획안 — 확정 정정 반영

제공일: 2026-09-25. 누락됐던 `source_user_plan.md`를 사용자 첨부와 같은 메시지의 추가 설명으로 복원한다.

이 문서는 사용자 제공 내용의 보관·대조용이다. 2026-09-25 후속 답변 “3장이 된 순간부터가 맞아 그거로 반영해줘”에 따라 쿨다운 관련 문장·예시·측정 항목을 최신 확정으로 정정했다. 새 초대 보상으로 초대권 잔액이 3장이 된 순간부터 10시간 추가 적립을 기다리며, 기간별 누적 지급 3회 제한은 없다. 대기 중에도 남은 게임권은 쓸 수 있다. 기본권은 별도이며 장애 환급으로 쿨다운을 다시 시작하지 않는다. 그 외 예시 수치·경품·혜택은 운영값으로 확정하지 않는다. 이번 요청은 문서 저장·정정·검토이며 코드·배포 변경은 포함하지 않는다.

## A. 첨부 내용 — UX·트래킹·카피 (쿨다운 확정 정정 반영)

### UX 개선안

#### 유입

- 최대한 쉽게 클릭 해야 함.
    - 진입 장벽 없어야 함
    - 누르고 싶어야 함
    - 사기 링크 느낌이 나면 안됨
    - 상품이 명확히 보여야 함
    - 가능성 있어 보여야 함
- 대안
    - 전국 대학생 한정 표시
    - 경품 규모 및 상품 표시
    - 예상 경쟁률 표시
- 필수 행동
    - 제미나이로 만든 게임임을 각인 시키기
    - 대학생만 가능한 점 알려주기

#### 로딩

- 목적
    - 클릭 후 바로 신뢰 확정
    - 이 이벤트 운영 주최를 보여주기
    - 게임 / 경품 구조 이해시키기
- 대안
    - Google Student Ambassador × 대학생 한정 이벤트
    - 이 게임은 Google Antigravity를 활용해 제작했습니다
    - 각 단계 로딩 단계에 맞춰서 보여주기 (애니메이션처럼 흘러가게)
        - 공룡 점프 → 복주머니 → 즉시 결과

**로딩은 광고판처럼 많이 넣기보다 2~3초 동안 신뢰 + 기대감만 심는 게 좋음.**

#### **게임**

- **목적**
    - 진입한 사람이 **바로 이해하고 플레이**하게 만들기
    - 짧은 시간 안에 **재미 + 경쟁심** 만들기
    - 중도 이탈 없이 **보상 단계까지 보내기**
    - 자연스럽게 Google AI와 연결
- **현재 개선 포인트**
    - 게임 시작 전 설명이 길면 이탈 → **한 줄 규칙 + 바로 시작**
    - 첫 플레이가 너무 어렵거나 너무 쉬우면 재미 없음 → **초반 진입 쉽게, 후반 급격히 어려워지게**
    - 플레이 중 Google 맥락이 없음 → 작은 `Built with Google Antigravity` 배지 정도
    - 점수의 의미가 약함 → **내 점수 / 현재 순위 / 최고점**을 직관적으로
        - **구글 코인 먹여서 혹은 하트 먹으면 한번 죽어도 부활 가능하게 개선**
    - 죽은 뒤 허탈하게 끝나면 안 됨 → 바로 **“복주머니 열기”**로 연결
- **랭킹**
    - 현재 TOP3 진입 시 이름 / 연락처 / 학교 입력 요청
    - `최종 경품 지급은 이벤트 종료 시점 TOP3 기준`
    - 순위가 밀릴 수 있다는 점 명확히 안내

#### **재도전 바이럴**

- **목적**
    - 한 번 플레이하고 끝나는 것을 막기
    - 친구 공유를 **추가 랭킹 도전 기회**와 연결
    - 친구 반응을 기다리지 않아도 복주머니 보상은 바로 받을 수 있게 하기
- **진행 방식**
    - 게임 종료 후 `현재 순위 / 최고점` 노출
    - `주간 TOP3 경품` 강조
        - 1~3위 차등 기프티콘
    - `현재 3위까지 ○점 남았어요`처럼 순위 상승 가능성 표시
    - `친구에게 공유하고 재도전권 받기` CTA 제공
    - 공유 후에는 **복주머니 단계로 바로 진행 가능**
    - 친구가 초대 링크로 **유효 방문**하면 재도전권 +1 자동 적립
    - 사용자가 나갔다가 다시 접속해도 적립된 재도전권 유지
    - 재도전권으로 다시 플레이해 **랭킹 기록 갱신**
    - 재도전해도 복주머니는 추가 지급하지 않음
- **유효 방문 기준**
    - 초대 링크로 접속
    - 3초 이상 활성 상태
    - 1회 이상 클릭/터치
    - 동일 방문자는 1회만 인정
- **보상 제한**
    - 친구 초대 재도전권 **최대 보유 3장**
    - **새 초대 보상으로 잔액이 3장이 된 순간부터 10시간 추가 적립 쿨다운**
    - 10시간 후 남은 권리는 유지하고, 새 유효 방문으로 잔액 3장까지 적립 가능. 다시 3장이 되면 새 10시간 시작
    - 새 쿨다운이 설정된 사람에게 해당 쿨다운 안내를 한 번 노출
    - 오픈톡 등에서 링크가 대량 확산돼도 최대 지급량까지만 적립

#### 복주머니 진입

- **목적**
    - 재도전 여부와 상관없이 모든 사용자를 하나의 보상 단계로 합치기
    - 재도전은 점수·랭킹 경쟁용으로만 사용
    - 복주머니 중복 지급 방지
- **진행 방식**
    - 첫 게임 종료
    - → 재도전 여부 선택
    - → 재도전 안 함: 바로 복주머니
    - → 재도전 함: 추가 게임 진행
    - → 최종 플레이 종료 후 동일한 복주머니 단계 진입
- **핵심 원칙**
    - 재도전 횟수와 관계없이 **복주머니는 최종 1회만 지급**
    - 재도전권은 **추가 뽑기권이 아니라 기록 향상 기회**
    - 최종 최고 점수 기준으로 랭킹 반영
    - 복주머니 단계에서 당첨/미당첨 분기

#### 보상 공개

- **목적**
    - 당첨 결과를 바로 보여주지 않고 기대감 만들기
    - 단순 추첨보다 기억에 남는 경험 만들기
    - 당첨/미당첨 이후 행동으로 자연스럽게 연결
- **진행 방식**
    - 복주머니 3개 중 1개 선택
    - → 선택한 복주머니 오픈
    - → 안에서 복권 등장
    - → 직접 긁기
    - → 결과 공개
- **결과 분기**
    - **당첨**
        - 축하 화면
        - 대학생 재학 여부 확인 안내
        - 이름/연락처 입력
        - 운영팀 개별 연락 후 경품 지급
    - **미당첨**
        - 아쉬움 짧게 전환시키기
        - “경품과 별개로, 대학생 혜택도 챙겨가세요.”
        - 바로 `Gemini 대학생 1년 무료 혜택` 안내
        - 외부 링크 이동 CTA

#### Gemini 가입 전환 향상 전략

- **목적**
    - 혜택을 본 사용자가 실제 Gemini 혜택 페이지까지 이동하게 만들기
    - 단순 무료 혜택이 아니라 **가입 후 바로 쓸 이유**까지 제공
    - 바로 가입하지 않은 사람도 콘텐츠를 통해 다시 전환시키기
- **가입 편의성**
    - `혜택 받으러 가기`
    - 가입 링크 복사
    - 크롬에서 여는 방법 안내
    - 카카오톡으로 링크 보내기
    - 가입 절차를 짧게 안내해 진입 장벽 낮추기
- **혜택 강조**
    - 공식 혜택의 **기간 / 대상 / 실제 가치**를 명확히 표시
    - 추상적인 “무료 혜택”보다 체감 가능한 내용 중심
    - 혜택명·가격·조건은 실제 Google 공식 안내 기준으로 통일
- **가입 후 활용 이유 제공**
    - `이 게임도 Google Antigravity를 활용해 만들었습니다`
    - Gemini로 실제 할 수 있는 일을 바로 보여주기
        - 공부 / 과제
        - 발표·PPT
        - 취업 준비
        - 취업사진 등
- **외부 콘텐츠로 2차 전환**
    - 화면에 별도 응답을 받지 않고 바로 노출
    - `이미 Gemini를 사용 중이시라면`
    - **“4년 평균 4.26, 실제로 쓰는 Gemini 비밀 노트 받아가기”**
    - Notion 가이드로 연결
    - Notion 안에서도 `아직 혜택을 받지 않았다면 → Gemini 혜택 확인` CTA 노출
- **전환 구조**
    - `게임 → Gemini 혜택 → 바로 가입`
    - 또는
    - `게임 → 활용 가이드(Notion) → 필요성 체감 → Gemini 가입`

### UX 추가 개선

- **경품 구조 - 미정**
    - TOP3 경품 각각 얼마인지
    - 복주머니 경품 종류/수량
    - 당첨 확률
- **재도전 규칙**
    - 최초 게임권 몇 장
    - 최대 보유 3장 + 새 초대 보상으로 잔액 3장 도달 순간부터 10시간 쿨다운 확정
    - 쿨다운 후 다시 친구 유입을 받아야 충전되는지 - 친구 유입되어야 함
- **랭킹 종료 규칙 - 미정**
    - 이벤트 종료 정확한 시각
    - 동점자 처리 - **n빵 시상?**
    - 종료 시점 TOP3만 최종 지급
- **당첨자 확인**
    - 이름 / 연락처 / 학교
    - 대학생 확인을 어떤 방식으로 할지 - 학생증 & 제미나이 가입 캡쳐 여부
    - 운영팀이 연락 후 지급 완료 처리

### 트레킹 항목

#### 1. 유입

- **목적**
    - 어떤 링크를 통해 유저가 들어왔는지 확인
    - 유입 채널별 성과 비교
- **구분할 유입 링크**
    - 초기 홍보용 링크
    - 친구 초대/재도전 바이럴 링크
    - 경품 결과 공유 링크
    - 기타 제휴/학교별 홍보 링크
- **확인 지표**
    - 링크별 유입 인원
    - 링크별 신규 참여자 수
    - 링크별 게임 시작률
    - 링크별 최종 Gemini 링크 클릭률

---

#### 2. 로딩

- **목적**
    - 클릭까지 했는데 게임에 진입하지 않는 사람이 얼마나 되는지 확인
- **확인 지표**
    - 로딩 화면 진입자 수
    - 로딩 완료 전 이탈자 수
    - 로딩 이탈률
    - **몇 초 시점에서 이탈했는지**
        - 예: 0~1초 / 1~2초 / 2~3초
- 로딩 자체 소요시간은 우리가 통제하므로 별도 성능 지표로 중요하게 보지 않음

---

#### 3. 게임

- **확인 지표**
    - 게임 시작 인원
    - 게임 완료 인원
    - **게임 완료율**
    - 게임 중 이탈 인원 / 이탈률
    - **몇 초 플레이 후 이탈했는지**
    - 어느 난이도/단계에서 이탈했는지
- **게임 결과 지표**
    - 개인 점수
    - 개인 최고점
    - 현재 순위
    - 전체 점수 분포
    - TOP3 진입 여부

---

#### 4. 재도전 바이럴

- **확인 지표**
    - 전체 게임 참가자 중 몇 명이 친구 초대에 참여했는지
    - 1인당 공유 시도 횟수
    - 1인당 생성한 유효 초대 수
    - 초대 링크 실제 유입 인원
    - 유효 방문 인정 인원
    - 재도전권 지급 횟수
    - 재도전권 실제 사용률
- **공유 채널**
    - 카카오톡
    - 링크 복사
    - 기타 공유 방식
    - 가능한 범위에서 채널별 구분
- **쿨다운**
    - 새 초대 보상으로 잔액 3장에 도달하여 쿨다운이 시작된 인원
    - 10시간 후 다시 재도전권을 획득한 인원
    - 쿨다운 이후 재참여율

---

#### 5. 복주머니 선택

- **확인 지표**
    - 복주머니 화면 진입자
    - 실제 복주머니 선택자
    - 선택 전 이탈자
    - 이탈률
    - **몇 초 만에 이탈했는지**
    - 복주머니 선택까지 평균 소요시간

---

#### 6. 선물 공개

과정:

**복주머니 선택 → 복권 등장 → 긁기 시작 → 긁기 완료 → 결과 확인**

각 단계마다:

- 진입 인원
- 다음 단계 이동 인원
- 이탈 인원
- 이탈률
- **해당 단계에서 몇 초 머문 뒤 이탈했는지**

특히 결과별로 분리:

- 일반 경품 당첨자
- 미당첨 / Gemini 혜택 안내 대상

Gemini 결과가 나온 경우에는 별도로:

- 결과 공개 후 몇 초 머무는지
- Gemini CTA까지 스크롤/도달했는지
- CTA 보기 전에 이탈했는지
- CTA 본 후 이탈했는지

---

#### 7. 선물 수령

- 당첨 결과 확인 인원
- 수령 정보 입력 시작 인원
- 입력 완료 인원
- 입력 중 이탈 인원
- 입력 완료율
- 입력까지 걸린 시간
- 최종 운영 상태
    - 연락 대기
    - 운영팀 연락 완료
    - 경품 지급 완료

---

#### 8. Gemini 전환

- Gemini 혜택 화면 도달 인원
- CTA 실제 노출 인원
- Gemini 링크 클릭 인원
- 링크 복사 인원
- 카카오톡 공유 인원
- Notion 활용 가이드 클릭 인원

```jsx
Google AI로 만든 게임하고,
삼텐바이미 받자!

경품 예상 경쟁률 1:10
대학생 한정 참여 가능

```

#### 친구 추천 - 재도전링크

## B. 같은 메시지로 추가 제공한 상세 규칙

### 1. 친구 초대 기반 재도전권 시스템

### 목적

- 친구 초대 장벽을 최대한 낮춤
- 친구가 게임까지 완료해야 하는 부담 제거
- 단순 공유 버튼 클릭만으로 재도전권을 받는 어뷰징 방지
- 공유 후 친구 반응을 기다리지 않고 **복주머니는 바로 진행 가능**
- 친구 유입을 통해 이후 다시 접속해서 랭킹에 재도전하도록 유도

### 전체 흐름

1. 게임 종료 후 현재 점수 / 순위 확인
2. `친구에게 공유하고 재도전권 받기` CTA 노출
3. 사용자별 **고유 초대 링크 생성**
```ruby
<https://도메인.com/?invite=ABC123>
```

1. 공유한 사용자는 친구 유입을 기다리지 않고 **복주머니 단계로 바로 진행**
2. 친구가 링크를 통해 접속
3. 아래 조건 충족 시 `유효 방문` 인정
```diff
초대 링크로 접속
+
페이지 3초 이상 활성 상태
+
1회 이상 클릭/터치
```

1. 서버에서 중복·자기초대·지급 한도 확인
2. 통과하면 초대한 사용자에게 **재도전권 +1 자동 적립**
3. 초대한 사용자가 나갔다가 다시 들어와도 재도전권 유지
4. 재도전권으로 다시 게임해 **랭킹 기록 갱신**

### 핵심 원칙

- 재도전권은 **랭킹 기록을 높이는 추가 게임 기회**
- 재도전해도 **복주머니는 추가 지급되지 않음**
- 복주머니는 참가자당 최종 **1회만**
- 친구가 게임을 할 필요는 없음
- 단순 링크 공유만으로는 보상하지 않음

### 유효 방문 서버 검증
```diff
- 자기 자신의 링크인지
- 동일 방문자가 이미 인정된 적 있는지
- 현재 재도전권 지급 한도를 초과했는지
- 정상적으로 발급된 초대 코드인지
```

동일 방문자에 대해서는:
```scss
UNIQUE(referrer_id, visitor_id)
```

등의 DB 제약을 적용해 새로고침으로 중복 인정되지 않게 처리.

### 재도전권 제한

- 친구 초대 재도전권은 **최대 보유 3장**이며, 한 사이클 누적 지급 횟수 제한은 두지 않음
- 유효 방문자 100명이 동시에 들어와도 잔액은 최대 3장까지만 적립하고, 잔액 3장 도달 후 10시간 동안 추가 지급하지 않음
- 새 초대 보상으로 잔액이 3장이 된 순간 **10시간 추가 적립 쿨다운** 시작. 대기 중에도 이미 받은 게임권은 사용 가능
- 쿨다운 종료 후 다시 친구의 **새로운 유효 방문이 발생해야** 재도전권 획득 가능
- 10시간이 지났다고 게임권 3개를 자동 지급하지 않음
- 새 쿨다운이 설정된 사람에게 해당 쿨다운 안내 팝업을 한 번 표시

예시:
```css
친구 A 유효 방문 → +1
친구 B 유효 방문 → +1
친구 C 유효 방문 → +1

잔액 3장 도달
→ 그 순간부터 10시간 추가 적립 쿨다운
→ 대기 중에도 남은 게임권은 사용 가능

10시간 후
→ 새로운 친구 유효 방문 발생
→ 빈자리가 있으면 +1 적립
→ 잔액이 다시 3장이 되는 순간 새 10시간 시작

대기 없는 동안 잔액을 계속 3장 미만으로 유지하면
→ 누적 지급 3회를 넘겨도 횟수만으로 차단하지 않음
```

### DB 예시

`referral_visits`
```
referrer_id
visitor_id
qualified_at
reward_granted
cooldown_started_at
```

`ticket_ledger`
```makefile
participant_id
delta = +1
source_type = REFERRAL
source_id = referral_visit_id
created_at
```

추가로 참가자별:
```
invitation_balance
cooldown_until
```

또는 원장 데이터를 기준으로 서버에서 계산.

### 서버 처리 원칙
```
유효 방문 확인
→ 중복 확인
→ 현재 초대권 잔액과 진행 중 환급 예약 확인
→ 최대 보유 3장 확인
→ 쿨다운 확인
→ 조건 충족
→ 초대권 +1
→ 새 잔액이 3장이면 서버 시간 기준 새 10시간 쿨다운 설정
```

모든 보상 판정은 프론트가 아니라 **서버 + Supabase DB 트랜잭션**으로 처리.

### 2. 익명 사용자 식별 및 재접속·어뷰징 방지

### 목적

- 로그인 없이 바로 게임할 수 있게 함
- 같은 사용자가 나갔다 들어와도 기존 상태 유지
- 게임권 / 최고점 / 랭킹 / 친구 초대 / 복주머니 / 경품 기록 복원
- 새로고침이나 반복 접속을 통한 무한 참여 방지

### 기본 방식

사이트 로딩 단계에서 서버가 **익명 participant**를 자동 생성.
```
첫 접속
→ participant 생성
→ 랜덤 인증 토큰 발급
→ 브라우저 쿠키 저장
```

권장 방식:
```
Secure
HttpOnly
SameSite
```

쿠키 사용.

기기 고유번호, IMEI, 브라우저 fingerprint 등은 사용하지 않음.

### 재접속
```
사이트 재접속
→ 쿠키 확인
→ 기존 participant 조회
→ 기존 상태 자동 복원
```

복원 대상:

- 남은 게임권
- 최고 점수
- 현재 랭킹
- 친구 초대 현황
- 적립된 재도전권
- 쿨다운 상태
- 복주머니 사용 여부
- 미완료 경품 수령 정보

### 새로고침 대응

같은 브라우저에서는 participant가 유지되므로:
```css
새로고침
→ 새로운 게임권 지급 X
→ 새로운 복주머니 지급 X
→ 새로운 participant 생성 X
```

### 시크릿 모드 대응

시크릿 모드 자체를 확실하게 탐지·차단하려 하지 않음.

- 같은 시크릿 세션에서는 쿠키 유지
- 새로고침만으로 신규 참가자가 되지 않음
- 시크릿 창을 모두 닫고 다시 열면 신규 참가자로 생성될 가능성 존재

따라서 핵심은 **시크릿 모드를 막는 게 아니라 사용해도 얻을 수 있는 이득을 제한하는 것**.

### 어뷰징 방지

- participant별 최초 기본 게임권 지급 1회
- 복주머니 지급 participant당 1회
- 친구 초대권 최대 보유 3장, 새 초대 보상으로 3장 도달 시 10시간 추가 적립 대기
- 동일 추천 방문자의 반복 인정 차단
- 게임 시작 / 종료 / 추첨 / 수령 API 중복 호출 방지
- 짧은 시간 동안 과도하게 익명 participant가 생성되면 rate limit 적용
- IP만으로 사용자를 확정하거나 영구 차단하지 않음
  - 대학 Wi-Fi, 기숙사, 공용망 사용자를 오탐할 수 있기 때문

### 실제 경품 단계 추가 보호

금전 가치가 있는 보상은 익명 ID만으로 최종 지급하지 않음.

아래의 경우 대학생 여부 확인:

- 복주머니 실제 경품 당첨
- 이벤트 종료 시점 랭킹 TOP3

당첨자에게:
```
이름
연락처
학교
대학생 인증 자료
```

를 별도로 받아 운영팀이 확인 후 수동 지급.

### 핵심 구조
```
로그인 없음
→ 익명 participant 자동 생성
→ 동일 브라우저 자동 복원
→ 서버에서 참여 기록 관리
→ 어뷰징 제한
→ 실제 경품 단계에서 대학생 인증
```

### 3. Gemini 전환 및 외부 콘텐츠 트래킹

### 목적

- Gemini 혜택을 본 사람 중 몇 명이 실제 혜택 페이지로 이동했는지 확인
- 바로 가입하지 않고 활용 콘텐츠를 본 사람의 행동까지 분석
- 유입 채널별 Gemini 전환율 비교
- 어떤 화면과 콘텐츠가 전환에 효과적인지 확인

### Gemini 혜택 기본 이벤트

`gemini_cta_view`

- Gemini 혜택 CTA를 실제로 본 사용자

`gemini_link_click`

- Gemini 공식 혜택 페이지로 이동한 사용자

`gemini_link_copy`

- Gemini 가입 링크를 복사한 사용자

`gemini_share`

- Gemini 혜택을 카카오톡 등으로 공유하려고 한 사용자

### 외부 콘텐츠 트래킹

Gemini 혜택 화면에서 제공:

- **4년 평균 4.26, 실제로 쓰는 Gemini 비밀 노트**
- Gemini 공부 / 과제 활용법
- 취업 준비 활용법
- 취업사진 활용법
- 발표 / PPT 활용법

각 콘텐츠 클릭도 따로 기록.

예:
```
study_note_click
career_guide_click
job_photo_guide_click
presentation_guide_click
```

### Notion을 활용한 2차 전환

전체 흐름:
```
Gemini 혜택 화면
→ 바로 Gemini 가입 페이지 이동
```

또는
```
Gemini 혜택 화면
→ Notion 활용 가이드
→ Gemini 활용 필요성 체감
→ Gemini 혜택 페이지 이동
```

Notion 페이지 내부에서도:

> 아직 Gemini 혜택을 받지 않았다면
>
> → Gemini 대학생 혜택 확인

CTA 제공.

가능하면 Notion의 Gemini CTA는 별도 추적용 리디렉션 주소를 사용해:
```bash
우리 도메인/redirect/gemini?source=notion-study
→ 기록
→ 공식 Gemini 링크로 이동
```

처럼 **Notion → Gemini 전환도 측정 가능하게 구성**.

### 관리자에서 확인할 지표

- Gemini CTA 노출 고유 사용자 수
- Gemini 공식 링크 클릭 고유 사용자 수
- CTA를 봤지만 클릭하지 않은 사용자 수
- Gemini CTA 클릭률
- 링크 복사 수
- 공유 시도 수
- Notion 가이드 클릭 수
- 콘텐츠 종류별 클릭률
- Notion에서 다시 Gemini로 이동한 수
- 유입 채널별 Gemini 클릭률
- 기간별 전환율

예:
```
Gemini CTA 노출         1,000명
직접 Gemini 클릭         500명
Notion 가이드 이동       250명
Notion → Gemini 이동      80명
미전환                    170명
```

### 중요한 집계 원칙

- 이벤트 발생 횟수와 **고유 사용자 수를 구분**
- 같은 사람이 버튼을 10번 눌러도 전환 사용자 10명으로 계산하지 않음
- 개발 / Preview / 부하 테스트 데이터는 실제 지표에서 제외
- 개인정보는 분석 이벤트에 저장하지 않음
- 각 링크에 `source`를 구분해 어느 콘텐츠에서 전환됐는지 확인

### 확인 가능한 범위

확인 가능:
```
Gemini CTA 노출
→ 공식 링크 클릭
→ 링크 복사
→ 공유 시도
→ Notion 콘텐츠 방문
→ Notion에서 Gemini 링크 재클릭
```

확인 불가능:
```
Gemini 사이트 이동 이후
→ 실제 학생 인증 완료
→ 실제 혜택 등록 완료
```

Google 측에서 별도 전환 확인 수단을 제공하지 않는 이상 **실제 가입 완료율과 외부 링크 클릭률은 구분해서 표현**해야 함.
