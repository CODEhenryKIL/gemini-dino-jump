# 공룡 점프 — 1·2·3차 범위와 공통 결정표

작성 기준: 2026-09-23 / 사용자 첨부 기획안 + 이 대화에서 작성한 기존 1차 지시서

대상 저장소: https://github.com/CODEhenryKIL/gemini-dino-jump

> 이번 문서는 작업 지시서 재작성이다. 실제 저장소·계정·배포의 현재 구현 상태를 새로 점검하거나 수정한 결과 보고서가 아니다.

## 1. 차수 재정의

| 차수 | 목적 | 포함 | 제외 | 완료 기준 |
| --- | --- | --- | --- | --- |
| 1차 | 운영 기반 + 확정된 서비스 규칙 + 측정 기반 구축 | Vercel/Supabase 이관, 익명 복원, 초대/쿨다운, 1회 추첨, 랭킹·수동 지급 관리, 단계별 측정, 관리자 집계, 기초 부하 테스트 | 최종 화면 디자인, 부활 게임 규칙 변경, 최종 경품값, 실지급, 공개 오픈 | 기존/최소 화면으로 테스트 경품 전체 흐름과 지표가 작동하고, 격리 환경 부하 결과 확보 |
| 2차 | 실제 사용자 경험·디자인·마케팅 완성 | 페이지별 문구/CTA/상태, 공유 카드, 로딩·게임·복주머니·긁기, 부활 기능, Gemini/Notion 동선, 실제 화면 이벤트 연결과 재검증 | 임의 경품·혜택 확정, 운영 DB 초기화, 실지급·공개 오픈 | 최종 Preview에서 모든 사용자 동선·계측·변경된 게임 검증이 작동 |
| 3차 | 운영값 확정 + 최종 검증 + 승인 후 공개 | 실제 경품 수량/확률, 종료/동점/수령 정책, 공식 혜택/링크, 개인정보 안내, 운영자, 도메인·Production, 최종 QA·종료·수동 지급 절차 | 승인 없는 구매·발송, 운영 데이터 삭제, Production 부하 테스트 | 운영값·승인·증빙·최종 QA 충족 후 공개, 종료·지급까지 운영 가능 |

**변경 핵심:** 기존 1차는 일부 서비스 규칙을 미정으로 남겼다. 이제 확정된 초대·쿨다운·1회 추첨·수동 지급의 서버 동작은 1차에 포함한다. 2차에서 같은 로직을 다시 만드는 것이 아니라 화면을 완성하고 연결한다. 부활처럼 게임 규칙 자체가 바뀌는 사항은 2차에 클라이언트와 서버 검증을 함께 변경한다.

이미 1차 작업을 시작했다면 새로 갈아엎지 않는다. 기존 구현을 읽어 완료/추가/충돌 항목을 분리하고 필요한 변경만 적용한다.

## 2. 공통 확정 사항

### 서비스와 참여

- 게이트 러너를 제거하고 공룡 점프만 유지한다. 이 사항은 앞선 대화에서 확정됐다.
- 로그인 없이 참여하며, 같은 브라우저의 유효한 쿠키가 유지될 때 참가자를 복원한다.
- 재도전은 랭킹 기록 향상용이다. 복주머니는 이 행사에서 참가자 ID당 1회이며 재도전 횟수와 무관하다.
- 친구를 기다리지 않고 복주머니를 열 수 있다. 복주머니를 이미 열었어도 이후 적립된 게임권으로 랭킹 재도전이 가능하다.
- 복주머니 화면에서 3개 중 1개 선택 → 복권 등장 → 긁기 → 결과 공개 흐름을 사용한다.

근거: 원문 54–79행, 337–359행, 105–110행, 469–511행.

### 친구 초대

- 초대 링크 방문 + 화면 활성 3초 이상 + 클릭/터치 1회 이상을 유효 방문 신호로 사용한다.
- 친구의 게임 완료는 요구하지 않는다. 공유 버튼 클릭만으로 보상하지 않는다.
- 서버가 자기초대·중복·한도·쿨다운을 확인하고 +1을 확정한다.
- 같은 초대자–방문자 관계는 반복 보상하지 않는다. 사이클이 바뀌어도 같은 관계를 새것으로 만들지 않는다.
- 한 사이클에서 초대로 받은 재도전권은 최대 3장이다. 단순히 현재 잔액이 3장 미만이라고 계속 지급하면 안 된다.
- 그 사이클에서 받은 3장을 모두 사용한 때부터 10시간 쿨다운이다.
- 쿨다운 종료 후 새로운 유효 방문으로 +1씩 다시 얻는다. 자동으로 3장을 채우지 않는다.

근거: 원문 342–388행.

### 랭킹과 실제 경품

- 현재 TOP3 진입 시 이름·연락처·학교 입력을 요청한다.
- 이는 최종 당첨 확정이 아니다. 이벤트 종료 시점 순위를 기준으로 최종 대상자를 판정한다.
- 실제 경품은 운영팀이 자격을 확인하고 개별 연락해 수동 전달한다.
- 지급 관리 프로그램은 기록·권한·재고·상태만 관리한다. 자동 선물 발송 기능은 필요하지 않다.

근거: 원문 47–50행, 171–174행, 546–565행.

### 측정

- 초기 홍보 / 재도전 초대 / 경품 결과 공유 / 학교·제휴 유입을 구분한다.
- 로딩·게임·복주머니·긁기·결과·수령에서 진입, 다음 행동, 이탈 추정, 체류시간을 측정한다.
- Gemini CTA 노출·클릭·복사·공유 시도, 콘텐츠별 Notion 이동을 구분한다.
- 승인되고 기술적으로 가능한 경우에만 Notion → Gemini 중간 이동을 추가 계측한다.
- 가입/학생 인증 완료는 외부 링크 클릭과 다르며 확인 수단이 없으면 수치로 만들지 않는다.

근거: 원문 176–312행, 656–665행, 714–723행.

## 3. 원문에서 충돌하거나 보완이 필요한 부분

아래는 원문의 확정 사항으로 조용히 바꾼 것이 아니라, **이번 지시서의 편집 적용 또는 별도 기술 보완 제안**이다.

### A. 복주머니를 ‘최종 플레이 종료 후’만 제공하는 문구

- 원문 87–96행은 모든 재도전을 마친 뒤 지급하는 것으로 읽힐 수 있다.
- 원문 57·64행, 323·337행과 앞선 대화는 친구 대기 없이 보상 진행을 명시한다.
- **이번 편집 적용:** 첫 정상 게임 완료 후부터 복주머니 1회 권한을 제공하고, 열기 시점은 사용자가 선택한다. 추후 랭킹 재도전은 독립적으로 계속 가능하다.

### B. 최초 기본 게임권의 ‘지급 1회’와 ‘수량 1장’

- 원문 537행의 최초 지급 1회는 중복 지급 방지 규칙이다.
- 원문 164행의 최초 게임권 수량은 미정이다.
- **이번 편집 적용:** 최초 지급 처리는 한 번만 하되 수량은 설정값으로 둔다. 테스트에서 1장을 쓰더라도 운영 확정으로 보지 않는다.

### C. 경품 당첨자도 Gemini 혜택을 보게 하는 동선

- 원문 보상 공개에는 미당첨자 분기에서만 명시돼 있다.
- 앞선 대화에서 당첨자는 수령 신청 후 같은 혜택 안내로 연결하기로 보완했다.
- **이번 편집 적용:** 당첨/미당첨 모두 혜택 안내로 갈 수 있다. 가입은 이미 얻은 경품을 인질로 잡는 조건으로 새로 추가하지 않는다.

### D. 유효 방문과 익명 ID의 한계

- 3초+터치 신호와 쿠키는 사람·친구 관계·재학생 여부의 증명이 아니다.
- **기술 보완:** 같은 participant 자기초대는 막되, 다른 브라우저로 새 ID를 만든 같은 사람을 완전히 식별한다고 보장하지 않는다. 수령 자격 확인과 중복 수령 정책은 별도다.

### E. 이탈·공유·외부 콘텐츠 측정 표현

- 브라우저 강제 종료에서 마지막 신호는 누락될 수 있다. 이탈 시각은 ‘마지막 관측 시점/추정’으로 구분한다.
- 카카오톡 버튼·복사 버튼을 기록할 수 있어도 실제 보낸 대화방·수신자·전달 횟수가 확인되는 것은 아니다.
- Notion으로 나가는 클릭은 Notion 본문 열람·정독을 뜻하지 않는다. Notion 자체 조회 지표와 이벤트 사이트 참가자별 퍼널을 자동 연결한다고 가정하지 않는다.
- 원문 684–688행의 ‘미전환 170명’은 중복 집합과 관측 기간이 정의되지 않아 그대로 계산할 수 없다. 직접 클릭/가이드 클릭/가이드 경유 재클릭을 더해 빼지 말고, 같은 노출 집단의 확인 가능한 고유 클릭 집합으로 계산한다.

공식 기술 참고: MDN pagehide, MDN share, Notion 페이지 분석.

## 5. 작업 방식과 권한

- 이 문서와 해당 차수 지시서를 함께 에이전트에게 전달한다.
- 먼저 실제 구현 상태를 읽고, 해당 차수의 누락분만 수정한다.
- 설계만 제안하지 말고 해당 차수 범위의 코드·문서·테스트를 완료한다.
- 계정 연결이나 유료 리소스 승인이 없으면 우회하지 않는다. 가능한 로컬 작업을 마치고 원격 미검증을 표시한다.
- 차수 전환 시 `phaseN-report.md`와 커밋·migration·이벤트 버전을 남긴다.
- Production 변경·DNS 전환·공개·실제 지급은 3차에서도 단계별 승인 전까지 하지 않는다.
- ‘1차 완료’는 기술·규칙 검증 완료이지 행사 공개 승인과 동의어가 아니다.
