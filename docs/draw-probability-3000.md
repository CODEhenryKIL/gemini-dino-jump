# 남은 경품 / 향후 3,000회 확률 변경

## 확정 기준

- 신규 사람 수가 아니라 **재뽑기를 포함한 앞으로 총 3,000회 추첨**.
- 적용 시점의 미당첨 실제 경품 전체를 사용한다. 기존 당첨·수령·게임·뽑기권 기록은 유지한다.
- 첫 회 상품별 확률 = 적용 시점 상품별 남은 수량 / 3,000.
- 매 회 남은 자리에서 균등 비복원 추첨한다. 이후 회당 확률 = 남은 상품 수량 / 남은 활성 자리 수.
- 활성 자리를 모두 사용하면 Gemini 혜택만 계속 제공한다. 1인 최대 10회, 검증 101점 이상 조건은 유지한다.

## 저장 및 호환

기존 5,000개 물리 자리와 63개 경품, 운영 manifest는 바꾸지 않는다.
campaign.settings.draw_pool_policy에 활성 자리 번호 상한, 시작 시 남은 개수, 확률 버전, 적용 시각, 기존 데이터 검증 해시를 저장한다.
상한은 적용 시점 미사용 자리를 정렬한 3,000번째 번호다. 모든 미사용 실제 경품이 상한 안에 있어야 적용할 수 있다.
제외한 BENEFIT 자리는 삭제하거나 당첨 처리하지 않는다.

새 서버는 추첨 잠금을 얻은 뒤 캠페인 설정을 다시 읽고, 자리 수 계산과 선택 모두 같은 상한을 적용한다.
DB 트리거는 정책 버전이 맞지 않는 구버전 서버의 신규 추첨과 상한 밖 배정을 차단한다.
기존 결과 조회·긁기 완료·수령 정보에는 신규 추첨 차단을 적용하지 않는다.
prize.probability 열은 기존 추첨판 모드에서 사용하지 않는 이전 설정값이다. 실제 확률 조회는 활성 자리 집계를 사용한다.

## 적용 순서

1. 격리 로컬 DB에서 신규 회귀 테스트와 운영 설정 검사 실행.
2. 정책 미설정 상태에서 보호 트리거 설치 (기존 동작 유지).
3. 검증한 커밋만 별도 배포하고 공개 정식 주소를 새 버전으로 전환.
4. HTTP 상태, 정식 배포 ID, 운영 DB 상태 확인.
5. docs/sql/activate-draw-pool-3000.sql 실행.
   - 운영 전환 잠금 → 추첨판 잠금 순서.
   - 현재 잔여 재고·3,000자리·모든 경품 포함을 검증.
   - 캠페인 설정과 확률 버전만 수정.
   - 기존 draw/claim/slot/inventory/credit 전체의 변경 없음 검증.
   - 이미 같은 정책 적용 상태라면 다시 시작하지 않음.
6. 실제 운영 추첨은 소모하지 않고 읽기 조회로 활성 잔여 수, 상품별 확률, 공개 서비스 상태 확인.

## 되돌리기

이 정책 적용 후 구버전 코드만 되돌리면 신규 추첨이 차단된다.
되돌림이 필요하면 동일 잠금 순서 아래 정책을 제거하고 previous_probability_version을 복구한 뒤 구버전으로 되돌린다.
이미 소비한 자리와 권리를 복구하거나 재추첨하지 않는다.
제외했던 BENEFIT 자리가 다시 포함되므로 잔여 회당 확률이 낮아지는 점을 운영자가 확인해야 한다.
